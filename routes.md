# Package Map & Tags

LLM-oriented reference. Each package described with purpose, key exports, and search tags.

---

## `main`

`./main.go`

Entry point. With no args, creates `context.Context` with `SIGINT/SIGTERM` cancellation and calls `app.Run()` (the HTTP service). Two subcommands share the binary: `crawl` runs the Telegram subscription crawler loop (`internal/crawl`, configured via `CRAWL_*` env), `classify <url>` classifies one URL and exits 0 (live subscription) / 1 (not) / 2 (usage).

**Tags:** `entrypoint`, `root`, `signal`, `main`, `subcommand`, `crawl`, `classify`

---

## `internal/app`

`./internal/app/app.go`, `pprof.go`

Application bootstrap: loads config, creates `Processor`, wires the config watcher and reloader, starts HTTP server, handles graceful shutdown.

**Key exports:**
- `Run(ctx) error` — main lifecycle

**Constants:**
- `defaultConfigPath = "./config/config.yaml"` — path passed to `config.Load`, `reload.NewReloader`, and `reload.NewWatcher`
- `shutdownTimeout = 15s` — server drain budget; above the 5s DNS/ASN lookup an in-flight request can be blocked in, so a routine SIGTERM does not exit non-zero. Expiry is a warning, not an error
- `controllerStopTimeout = 5s` — bound on joining the stable worker; `shutdownTimeout + controllerStopTimeout` must stay under the supervisor's `stop_grace_period`

**Internal functions:**
- `startMetrics(addr, m, logger) (*http.Server, error)` — binds the metrics listener with `net.Listen` BEFORE returning, so a port conflict is a startup error instead of a detached goroutine's log line; `srv.Addr` reports the bound address. Callers skip an empty addr
- `restoreStableList(cfg, logger) *stable.Holder` — builds the worker's holder and seeds it with `stable.LoadSnapshot(cfg.Subscriptions.SnapshotPath, logger)` when that returns non-nil, so `/stable.txt` serves the previous run's list from the first request. An unusable or absent file leaves the holder empty and startup carries on
- `stopController(ctl, logger)` — cancel + join the stable worker under `controllerStopTimeout`, degrading a non-cooperative stage to a warning instead of a hung shutdown
- `gracefulShutdown(ctx, srv, logger) error` — drains the server within `shutdownTimeout`; a deadline expiry is logged at warn and returns nil, anything else is wrapped as an error

**Wiring (inside `Run`):**
- Builds `server.Holder` seeded with the startup `Snapshot`, whose `Svc` and `Worker` fields both hold the one `*preprocess.Processor` — the second is the wider `stable.Filterer` the worker's closure reads (`holder.Load().Worker`), so a reload swaps both halves at once
- Restores the persisted stable list before the server starts (`restoreStableList`), so a restart no longer answers `503` for a whole cycle — measured at 58 minutes on a 68266-node pool. The same path is handed to `stable.NewController`, which bakes it into the `Checker`
- Creates `server.New(logger, listen, holder)` (no longer passes `svc`/`groupsMap` directly)
- Creates `reload.NewReloader` seeded with startup `cfg` + `svc`
- Creates `reload.NewWatcher` with `reloader.Reload` as the `onChange` callback
- Runs watcher in a goroutine under a derived cancellable context; a deferred cancel+join (`<-watcherDone`) runs before the `stopController(ctl)`/`gbStore.Close()` defers on EVERY return path (incl. listen error), so an in-flight reload can never race teardown

**Uses:** `config`, `geoblock`, `log`, `preprocess`, `reload`, `server`, `stable`
**Tags:** `bootstrap`, `wire`, `shutdown`, `lifecycle`, `hot-reload`

## `internal/config`

`./internal/config/config.go`

YAML config loading and validation. Uses `gopkg.in/yaml.v3` with **`KnownFields(true)`**: `config.yaml` and both overlays decode strictly, so a misspelled key fails the load naming the key instead of silently falling back to the default (an empty or comment-only overlay still loads — the decoder's `io.EOF` is not an error). `Load` merges sibling overlays when present — `sources.yaml` (curated subscription sources) and `private.yaml` (crawler-managed sources) — appending their `subscriptions.sources`; a read error other than not-exist fails the load. Also provides diff helpers used by the reloader to decide what changed.

**Key types:**
- `Config` — root config struct (`log`, `server`, `geo`, `resolver`, `filters`, `annotate`, `groups`, `subscriptions`, `geoblock`, `deadcache`, `fetch`)
- `GeoConfig` — `geo.geofeed` (`GeofeedConfig`) + `geo.dbip` (`DBIPConfig`) + `geo.registry` (`RegistryConfig`) + `geo.asn` (`ASNConfig`) + `geo.cloudflare` (`CloudflareConfig`); the shared geo providers used by the country/asn filters and by annotation, each named after the DATA SOURCE it queries. Provider name constants: `ProviderGeofeed`/`ProviderDBIP`/`ProviderRegistry`/`ProviderASN`/`ProviderCloudflare`
- `GeofeedConfig` — `sources` + `refresh_interval *time.Duration` with `Validate() error` method. Unset `refresh_interval` defaults to 24h; explicit `0` means "load once, never refresh". The dbip/registry siblings read `0` differently — see below
- `ASNConfig` — `timeout` + `cache_ttl` (ASN deny patterns now live on an `{type: asn}` filter entry, not here)
- `DBIPConfig` — `url` + `refresh_interval *time.Duration` for the DB-IP Country Lite download (annotate provider `dbip`); defaults built in (monthly `{yyyy-mm}`-templated gzip-CSV URL, 24h). Unlike `GeofeedConfig`, an explicit `0` is coerced to the 24h default, which is what it meant before the field became a pointer: freezing a month-stamped mirror for the process lifetime has no legitimate use (refresh rarely with a long interval instead), and a non-positive interval also makes `preprocess.geoDB.staleLocked` return before it consults `retryAt`, so a failed initial download could never retry. A negative value is still rejected by `Validate`. The literal `{yyyy-mm}` expands to the current UTC month at fetch time; `validateDownloadURL` requires an absolute https URL (placeholder substituted before parsing)
- `RegistryConfig` — `urls` + `refresh_interval *time.Duration` for the RIR delegated-extended downloads (annotate provider `registry`), one URL per RIR; defaults built in (the five `delegated-*-extended-latest` files, 24h), and `refresh_interval` carries `DBIPConfig`'s explicit-`0`-means-default semantics. **APNIC's default URL points at `ftp.lacnic.net`, not `ftp.apnic.net` and deliberately not `ftp.ripe.net`:** APNIC's host does not echo the legacy session ID in its ServerHello, so `crypto/tls` refuses the handshake and `LoadRegistry` skips that RIR (`sources_failed=1`, 255972 ranges instead of 330937, 97.30% coverage instead of 99.85%). RIPE and LACNIC both serve the file byte-identically under APNIC's own published `.md5`, so the mirror choice is about blast radius, not fidelity — and what `LoadRegistry`'s survive-one-outage promise is worth is the RANGES behind the worst host, not the number of distinct hosts: the five URLs sit on four of them either way (`ftp.lacnic.net` serves both the APNIC mirror and LACNIC's own file), so only the weights tell the candidates apart. Hanging APNIC off `ftp.ripe.net` would put `ripencc`+`apnic` = 201810 of 330937 ranges (61.0%) behind one host, where LACNIC leaves the worst host at ripencc's own 126845 (38.3%), the floor no mirror choice can beat, and `ftp.arin.net` (163160, 49.3%) falls to the same rule — see `defaultRegistryURLs` and `assertRegistryHostConcentration`
- `CloudflareConfig` — `timeout` + `concurrency` for the cdn-cgi/trace probe behind the `cloudflare` ANNOTATE provider (defaults 15s, 8). It is Cloudflare's own geo-IP database, whose verdict arrives as the `loc=` line; the difference from its siblings is not the kind of answer but the question — it is asked about the address the traffic LEFT from, not the address the resolver returned. No gate: a bad answer costs tag accuracy, never survivors, and `filters` cannot name it. **There is no `endpoint` key**, deliberately: `stable.parseTrace`/`validCountry` encode Cloudflare's documented reserved `loc` values (`XX`, `T1`) and its uppercase convention, so no other VENDOR's endpoint can satisfy the parser, and a key whose every cross-vendor value silently yields "unanswered" is a false affordance (another Cloudflare-fronted host WOULD parse — `/cdn-cgi/trace` is served on every domain Cloudflare proxies — which is why that substitution belongs in the constant, not in a key). The URL is `stable.cloudflareTraceURL`; tests reach an `httptest` server through the unexported `MihomoProber.traceEndpoint` field
- `Groups` — `map[string][]string` with `Validate() error` method
- `LogConfig` — `level` (`yaml:"level"`, default `"info"`)
- `FilterConfig` — one entry in the unified `filters:` list. `type` selects the filter (`country`/`asn`/`cidr`/`gemini`/`claude`/`chatgpt`/`tidal`/`bandwidth`); type-specific fields: country → `provider` (`geofeed`|`asn`, default `geofeed`), `exclude_groups`, `exclude_countries`; asn → `deny_patterns`; cidr → `urls`, `file_type` (default `raw`), `refresh_interval *time.Duration`; bandwidth → `min_mbps *int`, `test_url`, `timeout`, `concurrency`; gemini/claude/chatgpt/tidal → optional overrides (`marker`/`model`/`endpoint`/`key_file`/`key_var`/`api_key`/`timeout`/`concurrency`/`version`) merged over `geoblock.{gemini,claude,chatgpt,tidal}` (a field the type's merge does not read — a `model` on a tidal entry — is accepted by validation and then silently ignored). **`exclude_groups`/`exclude_countries` are worker-only**: their single consumer is `Config.DeniedCountries()` (`/stable.txt`); preprocess never receives them, so on `GET /` the country constraint comes from the query params alone — and only where a `country` entry exists at all, since `buildFilters` constructs nothing for an absent type while `server.go` still answers `400` for a request naming no country parameter. The cidr entry's `refresh_interval` carries `DBIPConfig`'s reading for `DBIPConfig`'s reason — unset **or explicit `0`** is the 24h `defaultGeoDBRefresh`, a negative value is rejected — and **at most ONE cidr entry may exist**: `urls:` is already the union, so a second entry could only mean intersection, and one live store is what keeps the reload carry-over a single value. The LIST ORDER is load-bearing for the IP stage and unvalidated: `buildFilters` appends in written order and `processNode` stops at the first filter that empties the IP slice, so `cidr` written after `asn` spends a Cymru round trip per IP on nodes the allow-list would have discarded for free
- `AnnotateSpec` — one entry in the ordered `annotate:` list: `tag` (`GEO`, the only accepted value) + `providers` (ordered lookup chain over `cloudflare|geofeed|dbip|registry|asn`, first provider that answers wins; required, defaulted to `[geofeed]`; unknown and duplicate providers rejected — the retired `geotrace` spelling is rejected by that same check, with no back-compat). Any other tag is rejected as unknown, `IP` and `ASN` included: both tags were removed outright (nothing consumed them, no config selected them), though `rewrite.isKnownTag` still STRIPS an upstream-authored `[IP:…]` / `[ASN:…]`. One accepted tag does not collapse the list: entries render in order and may repeat, and an empty list disables annotation. Repetition reaches BOTH stages: rendering emits one tag per entry, and `preprocess.countryChainOrder` concatenates EVERY `GEO` entry's chain. **There are two shipped configs now, and they differ here.** `config/config.yaml` chains `[cloudflare, geofeed, dbip, registry]`; `config-vassago/config.yaml` chains `[geofeed, dbip, registry]`, dropping `cloudflare` because that instance gates on the ENTRY address while the trace places the EXIT one, at one request per survivor. `asn` is accepted and absent from both (measured zero marginal hits; `AGENTS.md` carries the mechanism), which `preprocess.TestShippedConfigDropsASNButKeepsTheCapability` pins from both sides — it reads `config/config.yaml` specifically: that file must not name `asn`, and the same file with `asn` appended must still load and still build the resolver
- `IPFilterSpec` / `NodeFilterSpec` — parsed views of `filters` consumed by the two builders: `IPFilterSpecs()` returns country/asn/cidr specs (preprocess; country/asn carry `Type`/`Provider`/`DenyPatterns`, cidr carries `URLs`/`FileType`/`RefreshInterval`), `NodeFilterSpecs()` returns gemini/claude/chatgpt/tidal/bandwidth specs (stable, the API specs merged over geoblock, bandwidth carrying entry params). `IPFilterSpec.RefreshInterval` is the DEFAULTED duration, so a `Config` assembled in code rather than loaded from YAML skips `applyFilterDefaults` and projects `0` here — which `preprocess.cidrStore.staleLocked` reads as "never refresh"
- `GeoBlockConfig` — `db_path` + `ttl` + `Gemini GeminiConfig` + `Claude ClaudeConfig` + `ChatGPT ChatGPTConfig` + `Tidal TidalConfig` (per-node geo-block store plus the base params of every through-node GATE; tidal's live here for uniformity although it never writes to the store); own `validate()` rejects negative ttl/timeouts/concurrency for every sub-block. Every member drops nodes — the cdn-cgi/trace probe used to sit here and does not, having moved to `geo.cloudflare`
- `GeminiConfig` — `endpoint`/`model`/`marker`/`api_key`/`key_file`/`key_var`/`timeout`/`concurrency` (base params for the `gemini` filter); `APIKeyResolved()` reads the key inline or from `key_file` (agenix `KEY=VALUE`). The `gemini` filter is enabled by listing `{type: gemini}` in `filters`.
- `ClaudeConfig` — keyless counterpart for the `claude` filter (`endpoint`/`marker`/`version`/`timeout`/`concurrency`)
- `ChatGPTConfig` — keyless params for the `chatgpt` filter (`endpoint`/`marker`/`timeout`/`concurrency`); defaults `https://api.openai.com` + `unsupported_country`, the code OpenAI's `/compliance/cookie_requirements` returns (403) for an egress it refuses
- `TidalConfig` — keyless params for the `tidal` filter (`endpoint`/`timeout`/`concurrency`); default `https://api.tidal.com`. `GET /v1/country` answers 200 for an egress Tidal accepts; where it refuses one, the request never reaches the API (CloudFront 403 + HTML, measured from a RU egress). The gate is **fail-closed** on the status alone: kept only on 2xx, and since redirects are not followed a 3xx interstitial is a refusal too. The body is not read — the country it carries gates where a subscription can be bought, not where an existing subscriber streams — so a 2xx from something other than Tidal (ISP block page, captive portal) counts as passed
- `BandwidthConfig` — through-node download-speed gate params (`test_url`/`min_mbps *int`/`timeout`/`concurrency`), sourced from a `{type: bandwidth}` filter entry. Unset `min_mbps` defaults to 5; explicit `0` = no floor (annotate only).
- `FetchConfig` — `timeout` (per-subscription fetch deadline, default 3s)
- `SubscriptionsConfig` / `CheckConfig` — `/stable.txt` worker settings (`interval`, `sources`, `check.*`). `check` carries probe params only — no `filters`/`bandwidth`/`exclude_*`, which moved to the top-level `filters:` list — and "probe" rather than "URL test" because `check.timeout` also sets the reachability pre-check's dial budget (`precheckDialBudget`, halved per attempt). `SubscriptionsConfig.Validate` checks `interval` and the whole `check` block **unconditionally** and the source list separately (`validateSources`, re-run after each overlay merge), so a bad prober param cannot boot clean on empty overlays and then fail every reload once the crawler writes its first source. `CheckConfig.validate` parses `expected_status` with mihomo's `utils.NewUnsignedRanges` (same parser the prober uses) and requires `test_url` to be an absolute http(s) URL (the URL test egresses through the proxy node, so host-side SSRF rules don't apply). `snapshot_path` (empty disables) is where the worker persists the list it just published so a restart serves it instead of `503`; it takes no validator beyond the strict decoder, exactly like the three other path keys in the SCHEMA (`geoblock.db_path`, `geoblock.gemini.key_file`, `filters[].key_file`) — none of the four is checked at load, and a `key_file` is not even opened until `APIKeyResolved` reads it at Apply time. `config/config.yaml` sets three of those four — this key, `geoblock.db_path` and `geoblock.gemini.key_file`, but not `filters[].key_file` — and it is that narrower population, minus this key itself, that `AGENTS.md` enumerates when it explains why this value is absolute. `config-vassago/config.yaml` sets this key alone: it ships no `geoblock` block at all, so `app.Run` opens no store for that instance and the only file it writes into its `/config` is the snapshot. `snapshot_path` is also the one member of the block a reload does NOT re-apply (see `StoresChanged`)
- `SubscriptionSource` — `name` + `url` + `body` (`yaml:"body,omitempty"`). A source carries **either** a fetched `url` **or** an inline `body` (base64/raw newline-joined node URIs). `Subscriptions.Validate` requires a valid `name` (`sourceNameRe`) for both; when `body` is set the URL check is skipped (URL may be empty), otherwise `fetch.ValidatePublicHTTPSURL(url)` is enforced — a source with neither is rejected. `body` is used by the crawler's inline-node harvest (`tg-inline`).
- `DeadCacheConfig` — `ttl` (in-memory short-TTL cache of probe-dead nodes; skips re-probing them; default 2h)

**Key functions:**
- `Load(path) (Config, error)` — read + strict unmarshal (`decodeStrict`) + apply defaults + call `cfg.Validate()`
- `(*Config).Validate() error` — validates `resolver.address` (must be `host:port`; a portless value dials nothing and drops every node as a DNS failure), geo.geofeed sources, geo.dbip/geo.registry download URLs (absolute https), groups, the `filters`/`annotate` lists (unknown types/tags, country provider + exclude groups/countries, asn deny-pattern regexps, cidr `urls` — at least one, each through `fetch.ValidatePublicHTTPSURL` — plus `file_type`, a non-negative `refresh_interval` and the at-most-one-cidr-entry rule, api timeout/concurrency, bandwidth knobs, annotate provider chains), subscriptions/check, geoblock, log level (`zerolog.ParseLevel`), and rejects negative durations across all sections. `validateCountryList`/`validateCountryCode` are the shared ISO-code validators (the error is prefixed with the caller's path, e.g. `filters[0].exclude_countries`)
- `(*Config).IPFilterSpecs() []IPFilterSpec` / `(*Config).NodeFilterSpecs() []NodeFilterSpec` — split the unified `filters` list into the IP-stage (country/asn/cidr) and through-node (gemini/claude/chatgpt/tidal/bandwidth) specs the two builders consume
- `(*Config).DeniedCountries() filter.CountrySet` — the stable worker's country deny-set, expanded from every `country` filter entry's `exclude_countries` + `exclude_groups` (via `Groups`). The only reader of those two keys; a deny-set rather than the complement allow-set so a node no geo source can place is kept, not dropped
- `(*Config).AnnotateUsesProvider(name string) bool` — true when any `annotate` chain names the provider. The stable worker asks for `ProviderCloudflare` to decide whether to run the trace probe at all: it costs one request through every survivor, so an offline-only chain must never arm it
- `(*GeofeedConfig).Validate() error` — validates sources are non-empty with valid types
- `(Groups).Validate() error` — validates group names and 2-letter country codes
- `Equal(a, b Config) bool` — deep equality check via `reflect.DeepEqual`; used by reloader to skip no-op reloads
- `GeofeedSourcesChanged(old, newCfg Config) bool` — true when `geo.geofeed.sources` differ; reloader uses this to decide whether to carry over the existing lookup
- `DBIPChanged` / `RegistryChanged (old, newCfg Config) bool` — true when the `geo.dbip` / `geo.registry` block differs; the reloader carries the loaded lookup over when they don't, avoiding a multi-MB re-download per reload
- `CIDRFiltersChanged(old, newCfg Config) bool` — true when the cidr entry's `urls`/`file_type`/`refresh_interval` differ. Diffed over `IPFilterSpecs()`, so it compares the DEFAULTED values and no edit elsewhere in the file can move it; the reloader carries the loaded allow-list over when it is false, so a `log.level` edit neither re-downloads the list nor re-merges it
- `ResolverChanged` / `ASNChanged (old, newCfg Config) bool` — true when the whole `resolver` / `geo.asn` block differs; the reloader carries the live resolver (and its warm DNS/Cymru cache) over when they don't, so the configured `cache_ttl` is reachable instead of being reset by every reload. Whole-block granularity is deliberate: the timeouts and TTLs are baked into the resolver at construction
- `ListenChanged` / `MetricsListenChanged(old, newCfg Config) bool` — true when `server.listen` / `server.metrics_listen` changed; reloader logs a warning and ignores the change (both listeners start once; restart required)
- `SubscriptionsChanged` / `GroupsChanged` / `FiltersChanged` / `ProberChanged` / `AnnotateChanged (old, newCfg Config) bool` — reloader hands the new config to the stable worker (`Controller.Apply` -> `Checker.Reconfigure`; the worker is never restarted) when any is true; `FiltersChanged` diffs the `filters` list, `AnnotateChanged` diffs the `annotate` list, `ProberChanged` compares the through-node prober sub-configs — geoblock's gemini/claude/chatgpt/tidal plus `geo.cloudflare` (store-only geoblock fields belong to `StoresChanged`). `geo.cloudflare` is gated here and NOT by `OptionsFromConfig` deliberately: the gate follows the CONSUMER, not the namespace. Its `geo.*` siblings are processor-side, this one is read only by the worker's post-probe trace stage, so inheriting their class would stop a `geo.cloudflare.timeout` edit reaching the running worker
- `StoresChanged(old, newCfg Config) bool` — true when `geoblock.db_path`/`geoblock.ttl`/`deadcache.ttl`/`subscriptions.snapshot_path` changed; those values are baked in at startup, so the reloader logs a restart-required warning. `subscriptions.snapshot_path` is the one member not named after its own store: it is excluded from `SubscriptionsChanged` (which otherwise diffs the whole block) because the `Checker` is handed the path at construction and never re-reads it, so re-applying the worker over an edit would claim a reach the value does not have
- `internal/reload/reload_coverage_test.go` — one classification table for every yaml leaf of `Config`, enforced twice: `TestReloadCoverageComplete` walks the struct (pointers dereferenced, slice/map element structs followed) so no key can ship unclassified, and `TestReloadClassificationMatchesBehaviour` mutates each key alone and asserts the declared class (live-processor / live-worker / live-both / live-other / restart-warned) is the path `Reload` actually takes. It lives in `internal/reload` because the behavioural half needs `OptionsFromConfig`. `geo.cloudflare.{timeout,concurrency}` are the table's deliberate oddity: every other `geo.*` leaf is live-processor, these two are live-worker because only the worker consumes them (see `config.ProberChanged`), and `TestReloadGatesMatchHelpers`'s `cloudflare` fixture drives a real `Reload` to prove the edit reaches `Controller.Apply` rather than only a processor rebuild. The cidr keys `filters[].urls`/`file_type`/`refresh_interval` are live-both, like the other IP-stage filter keys: the allow-list belongs to the processor, and `FiltersChanged` diffs the whole `filters` list so the worker is re-applied too. `coverageBase` therefore carries a sixth filter entry (`cidr`, index 5) so each of the three can be mutated alone

**Uses:** `fetch`, `filter`, `geofeed`, `mihomo/common/utils`, `zerolog`
**Tags:** `config`, `yaml`, `validation`, `startup`, `defaults`, `diff`, `reload`

## `internal/fetch`

`./internal/fetch/fetch.go`

Safe HTTP fetching. Only `https`, no userinfo, no proxy. The **SSRF IP policy lives in the HTTP client's dialer**, not the validators: `NewSafeHTTPClient` refuses resolved non-public IPs at dial time (private/loopback/link-local + CGN/benchmarking/class-E reserved ranges) and backs the shared client for user/content URLs; `NewUnrestrictedHTTPClient` keeps https-only + no-proxy but does **not** restrict IPs — used only by the crawler, which reaches `t.me` through a local fake-ip tunnel and follows scraped links (blind SSRF, no response reflected to any user).

**Key types:**
- `FileType` — `"raw"` | `"gzip"`
- `SubscriptionURL` — lightweight `string` type for subscription URLs
- `StatusError` — typed non-2xx response error (`Code int`, message `bad status: <code> <text>`); callers branch on the code via `errors.As` instead of parsing error text (the dbip previous-month fallback checks 404)

**Key functions:**
- `BytesWithType(ctx, url SubscriptionURL, limit, fileType) ([]byte, error)` — fetch + decode body (uses the shared guarded client). Reads one byte past `limit`, so a body that overruns the cap is distinguishable from one that fills it, and sizes the buffer from `resp.ContentLength` for a `raw` fetch (`readBody`): the transport sets `DisableCompression`, so a raw response arrives identity-encoded and its `Content-Length` survives — measured 2026-08-14, 145 of the 147 configured sources answering 200 state one. `io.ReadAll` is still the fallback for the two that do not, and it costs a measured 2.24x the body in transient garbage, every byte of it live at once because it consolidates its whole chunk list into a final right-sized slice. The header is a claim, never a bound: a body that runs past it is grown into, and only `limit` stops the read. A `gzip` fetch gets no hint — there `Content-Length` is the COMPRESSED size and would systematically undersize
- `ValidateHTTPSURL(url SubscriptionURL) error` — scheme/host/userinfo check only; no IP restriction
- `ValidatePublicHTTPSURL(url SubscriptionURL) error` — `ValidateHTTPSURL` + reject a literal non-public-IP host (SSRF guard for the `/` endpoint and subscription sources). The non-public set covers the IPv4 reserved ranges plus the IPv6 special-purpose prefixes that embed an IPv4 target (`::/96`, `64:ff9b::/96`, `64:ff9b:1::/48`, `100::/64`, `2001::/32`, `2002::/16`, `fec0::/10`), which `Unmap` does not normalise. It also rejects a host whose EVERY dot-separated part is a number `inet_aton` accepts — decimal, `0x` hex or `0`-prefixed octal (`numericIPHost`). **That rule is the contract, not a list of spellings:** `netip.ParseAddr` answers for none of them, so each would otherwise pass the IP gate as a domain name and getaddrinfo would resolve it to the address it spells — measured under `CGO_ENABLED=1`, `2130706433`, `0x7f000001`, `127.1` and `0177.0.0.1` reach `127.0.0.1` while `0300.0250.0.1` reaches `192.168.0.1`, and the pure-Go resolver the shipped image pins answers `no such host` for all of them. A host is refused only when the WHOLE of it is such a number, so `12345.example.com` and `cafe.beef` still pass
- `ValidatePublicParsedHTTPSURL(u *url.URL) error` — `ValidatePublicHTTPSURL` for a caller that already parsed: same gates, same order, same error values, minus the parse it cannot redo. `crawl.candidate` uses it so a discovered URL is parsed once instead of twice
- `NewSafeHTTPClient() *http.Client` — guarded transport: non-public resolved IPs refused at dial time
- `NewUnrestrictedHTTPClient() *http.Client` — https-only, no proxy, **no IP guard** (crawler only)
- `MaybeDecode(resp, fileType) (io.ReadCloser, error)` — wrap gzip if needed; the gzip path is guarded against decompression bombs (the read fails once output passes the size floor AND exceeds a fixed ratio of the wire bytes consumed, so a few-KB archive can no longer inflate to the caller's whole byte limit)
- `ValidateFileType(fileType) error` — must be `raw` or `gzip`

**Constants:**
- `UserAgent` — sent on every outbound fetch; exported so `classify` presents the same identity a worker fetch would

**Tags:** `http`, `fetch`, `ssrf`, `security`, `gzip`, `download`, `client`, `redirect`

## `internal/geofeed`

`./internal/geofeed/geofeed.go`, `lookup.go`, `dbip.go`, `registry.go`

IP→country data sources and lookup: RFC 8805 geofeed CSV, the DB-IP Country Lite database, and the RIR delegated-extended registry files all parse into the same in-memory indexed lookup. Both address families now use a flat sorted slice with binary search plus a prefix-max array of range ends bounding the most-specific backward walk — the v6 linear scan is gone; v6 mirrors the v4 path over big-endian `uint128` words. Most-specific = smallest span among covering ranges; equal spans resolve to earliest input order.

**Key types:**
- `CountryCode` — strict 2-byte ISO country code (`[2]byte`) with `String()`
- `Entry` — `Prefix` + `Country` (`Country` is `CountryCode`)
- `Range` — inclusive `Start`/`End` (`netip.Addr`, same family) + `Country`; addr pairs rather than `netip.Prefix` because DB-IP and RIR v4 ranges are not CIDR-aligned
- `Source` — `URL` + `Type` (also used in config.yaml via yaml tags)
- `CountryLookup` — interface with `LookupCountry(ip) CountryCode`
- `SizedLookup` — `CountryLookup` + `Len() int`; implemented by the indexed lookups so the preprocess reload guards can compare a freshly loaded database against the live one

**Key functions:**
- `LoadAll(ctx, sources, logger) ([]Entry, int, error)` — fetch + parse geofeeds; skips a source that fails to fetch/parse (logs a warning) and errors only when NO source yields entries, so one flaky feed can't crash-loop startup. The middle return is the number of skipped sources: a partial load is still `err == nil`, so callers holding a good database (the preprocess background reload) use the count to refuse the swap
- `Parse(body) ([]Entry, error)` — parse geofeed CSV body (`parseLine`: one `ioutil.UnsafeString` alloc per line, then `strings.Cut`; `parsePrefixOrAddr` uses `addr.BitLen()` instead of hardcoded bit widths)
- `NewLookup(entries) CountryLookup` — indexed lookup from CIDR entries (prefixes convert to ranges)
- `NewRangeLookup(ranges []Range) CountryLookup` — indexed lookup from raw ranges (DB-IP / registry)
- `LookupCountry(lookup, ip) CountryCode` — helper forwarding to the configured lookup
- `ExpandMonthURL(url, now) string` — replaces the literal `{yyyy-mm}` with now's UTC month (DB-IP publishes per UTC calendar month)
- `LoadDBIP(ctx, url, logger) ([]Range, error)` — fetch + parse the DB-IP Country Lite gzip CSV; on a 404 for the current month (not yet published right after rollover) retries once with the previous month (`errors.As` on `*fetch.StatusError`); errors when both fail or nothing parses — the caller (preprocess `geoDB`) degrades to an empty lookup instead of failing startup
- `ParseDBIP(body) []Range` — `start_ip,end_ip,CC` lines, v4/v6 mixed; per-line tolerant (malformed, mixed-family, unordered, and `ZZ` lines skipped)
- `LoadRegistry(ctx, urls, logger) ([]Range, int, error)` — fetches the RIR delegated-extended files; skips (warns) any single failing RIR so one registry outage can't take down startup, errors only when NO ranges load, and reports the skipped-RIR count (mirrors `LoadAll`). Each source that loads gets an Info line carrying its header serial (`registry source loaded url=… serial=20260804 ranges=74965`). That is an OBSERVABLE and not a gate — nothing branches on it — but it is the only signal that a mirrored copy (APNIC's, see `defaultRegistryURLs`) is lagging: a file frozen months ago fetches 200, parses clean, reports `sources_failed=0`, and lands a range count well inside `swapRefusal`'s `minSwapRatio`
- `delegatedSerial(body) string` — field 2 of the delegated-extended version header (`2.3|apnic|20260804|188932||20260803|+1000`), which `ParseDelegated` itself drops because that field holds the serial where a record holds `ipv4`/`ipv6`; `""` when the body opens on a record instead of a header, so a record's type never reads as a serial. **The FORM is the publishing registry's, and the five disagree** — `apnic`/`lacnic`/`afrinic` write `YYYYMMDD`, `ripencc` a unix second count (`1785794399`), `arin` unix milliseconds (`1785848421615`) — so it is monotonic within a source and meaningless across sources
- `ParseDelegated(body) []Range` — `registry|cc|type|start|value|date|status` records; keeps only ipv4/ipv6 with status allocated/assigned and a real country (version header, summary rows, asn records, available/reserved, `ZZ`/`*`/empty countries skipped)
- `fetchBytes` / `timeNow` — package vars so tests stub the network fetch and pin the month templating

## `internal/cidrset`

`./internal/cidrset/cidrset.go`

IPv4 membership against a downloaded IPv4 allow-list — a ~30k-line CIDR file, and see README on why the shipped one is a worldwide scan artifact rather than an operator ACL — merged into sorted disjoint `[lo,hi] uint32` ranges so a lookup costs one binary search and no allocation. Fetching, file-type decoding and line iteration are the shared ones (`fetch.BytesWithType`, `ioutil.Lines`), so a source is an https URL with an explicit `raw`/`gzip` type exactly like a geofeed. IPv4-only by the same rule as the rest of the pipeline: a v6 line is skipped, not an error.

**Key types:**
- `Set` — immutable, merged, sorted, disjoint ranges plus the address total they admit; the zero value matches nothing. It carries no fail-closed policy of its own — a caller that must not run on an empty allow-list checks the size itself, which `preprocess.newCIDRStore` does
- `ipRange` (unexported) — one inclusive range as native `uint32`s, the form `Contains` searches

**Key functions:**
- `Parse(body) (Set, int)` — one prefix or bare address per line, since the upstream repo ships both forms (a bare address becomes a singleton range). A prefix is `Masked()` first, so a sloppy `1.2.3.4/24` still yields the whole /24. The second return counts skipped lines — anything that is not a valid IPv4 prefix or address, IPv6 included — and a skip never fails the body
- `Load(ctx, urls, fileType, logger) (Set, int, error)` — mirrors `geofeed.LoadAll` deliberately: a URL that fails to fetch, or that parses to zero ranges, is warned and counted in the middle return, and the error comes only when NO url yielded a range, so one flaky mirror cannot crash-loop startup. Merging runs ONCE over the union rather than per source, or two sources' adjacent ranges would never coalesce. `maxListSize` (16 MiB) bounds one decoded body; `fetchBytes` is a package var so tests stub the network
- `(Set).Contains(ip) bool` — `Unmap`, then binary-search the last range starting at or below the address; false for the empty set and for anything not IPv4. Allocation-free and lock-free — the set is immutable and its holder swaps it whole
- `(Set).Len() int` — the MERGED RANGE count. An operator-facing number for logs, and **not** the quantity a refresh guard may compare. It counts contiguous INTERVALS, not CIDRs: `newSet` coalesces any two ranges that TOUCH (`next.lo <= ranges[last].hi+1`, `cidrset.go:192`), where a CIDR tool merges only prefix pairs that are ALIGNED. **Do not "correct" this repo's 15649 against one.** Python's `ipaddress.collapse_addresses()` reports 30222 CIDRs over the identical `cidrwhitelist.txt`; both figures are right about different things, and a reviewer filed the 15649 as stale over exactly that gap and retracted
- `(Set).Covered() uint64` — how many addresses the set admits, and the only size a guard may compare, because the two move independently in BOTH directions. Not hypothetical: the same upstream also publishes `ipwhitelist.txt`, the pre-CIDR format, which renders the same space as the `.1` of every /24 — 141664 ranges for 141664 addresses against `cidrwhitelist.txt`'s 15649 ranges for 36265984, so 9x the ranges for 0.39% of the coverage. A `Len` guard would read the CIDR file failing over to the address file as healthy growth while the live set collapsed to nodes resolving to a literal `.1`. The other direction is ordinary maintenance: an upstream that consolidates adjacent prefixes shrinks the count over a strictly better dataset. `preprocess.swapRefusalSize` is the consumer, and this is the unit it is handed

**Uses:** `fetch`, `ioutil`
**Tags:** `cidr`, `allow-list`, `whitelist`, `ipv4`, `range`, `merge`, `binary-search`, `membership`

## `internal/filter`

`./internal/filter/filter.go`

Country filtering using a compact bitset (`[11]uint64`) for O(1) lookup of 2-letter country codes.

**Key types:**
- `CountrySet [11]uint64` — bitset for AA–ZZ (676 codes)

**Key functions:**
- `(*CountrySet).Has(country CountryCode) bool` — O(1) check
- `(*CountrySet).Add(part string) bool` — add a single country code (whitespace trimmed, case normalized); reports whether the token was a 2-letter code, so callers validating user input can reject the rest
- `(*CountrySet).Exclude(other CountrySet)` — remove one set from another
- `All() CountrySet` — return a set with all 676 2-letter codes set, and only those: the 28 bits above `ZZ` stay clear so a fully-excluded set compares empty
- `ParseAllowed(parts ...string) CountrySet` — parse `"DE,US,  nl  "` or `"DE", "US", "nl"` into bitset (uses `strings.SplitSeq`); unparseable tokens are ignored, use `Add` to detect them
- `Permits(allowed, denied CountrySet, country CountryCode) bool` — the country decision for one IP. `allowed` constrains only when it is not full; `denied` is matched positively
- `Permitted(lookup, ips, allowed, denied) []netip.Addr` — apply `Permits` to each IP's geofeed country, compacting the input slice in place
- `IsFull(s CountrySet) bool` — true when `s` contains every code (the `All()` set); as an allow-list it constrains nothing
- `IsEmpty(s CountrySet) bool` — true when `s` contains no code at all

The allow-list and the deny-list are deliberately asymmetric about the zero `CountryCode` that `geofeed.LookupCountry` returns for an IP no source covers. A non-full allow-list drops it (it is not in the list); the deny-list keeps it (it is in no excluded country). That is what makes `exclude_countries`/`exclude_groups` a deny-list rather than "all countries minus the exclusions": excluding RU must not drop every IP the geofeed cannot place.

**Uses:** `geofeed`
**Tags:** `filter`, `country`, `bitset`, `geo`, `permit`

## `internal/resolver`

`./internal/resolver/resolver.go`

DNS resolver for subscription node hostnames. Uses system DNS or custom address. Deduplicates IPv4 results. Process-wide TTL cache (RWMutex map): positive hits cached for `resolver.cache_ttl`, failed/empty lookups negative-cached for `resolver.cache_negative_ttl` (returned as empty result without error); zero TTLs disable caching entirely. Cache keys are cloned (`strings.Clone`) so they never pin the fetched subscription body backing array. Cache is capped at 16384 entries — on overflow expired entries are evicted, and if that frees nothing a bounded 1/8 sample of live entries is dropped (never a full wipe, which would take the hit rate to zero exactly when the working set is largest). The whole resolver, cache included, is carried across a config reload unless the `resolver` block changed — otherwise the crawler's hourly `private.yaml` rewrite would reset it long before `cache_ttl` elapsed. preprocess still isolates results once per request/hostname via a pooled resolved-map. When a custom `resolver.address` is configured, `PreferGo: true` is set on the `net.Resolver` so the custom `Dial` function is actually used (the cgo resolver ignores `Dial`).

**Key types:**
- `Resolver` — `timeout` + `lookup` (the one `*net.Resolver`, built in `New`) + TTL cache (`map[string]cacheEntry` under `sync.RWMutex`) + `sync.Pool` for resolved maps

**Key functions:**
- `New(timeout, address, cacheTTL, negativeTTL) *Resolver`
- `(*Resolver).Resolve(ctx, host) ([]netip.Addr, error)` — bare IPs returned directly, then cache, then DNS lookup through the stored `lookup`. One instance for the process is what makes `net.Resolver`'s singleflight group collapse concurrent lookups of the same host into a single wire query; a per-call instance has an empty group
- `(*Resolver).GetResolvedMap() map[string][]netip.Addr` — get pooled per-request hostname map
- `(*Resolver).PutResolvedMap(m)` — return map to pool

**Tags:** `dns`, `resolve`, `hostname`, `ip`, `pool`, `dedup`, `cache`, `ttl`

## `internal/asn`

`./internal/asn/resolver.go`

ASN resolver using Team Cymru DNS (`origin.asn.cymru.com` + `asn.cymru.com`). Results are cached in memory with a configurable TTL (`asn.cache_ttl`, default 24h; a zero/negative value falls back to `defaultCacheTTL`); failures are negative-cached for 5m (`negativeCacheTTL`, cancellation errors excluded) so an unreachable Cymru doesn't serialize per-node timeouts. The cache is capped at 16384 entries with evict-expired-then-sample-on-insert (same pattern as `internal/resolver`; the 24h TTL means nothing expires within a day, so a full map would otherwise wipe on every insert), and the resolver is carried across a config reload unless the `geo.asn` block changed. `CacheLen()` exposes the size. Currently IPv4-only. **It is no longer in the shipped `annotate` chain** — measured, it is a strict subset of a complete `registry` with zero marginal hits behind it (see `AGENTS.md`); the AS **name** is what it uniquely carries, so it still backs `{type: asn}` deny patterns and `{type: country, provider: asn}`.

**Key types:**
- `Result` — `Country` (`geofeed.CountryCode`) + `Name`
- `Resolver` — `timeout` + `cacheTTL`

**Key functions:**
- `New(timeout, cacheTTL) *Resolver` — a zero/negative `cacheTTL` falls back to the 24h default
- `(*Resolver).Resolve(ctx, ip) (Result, error)` — fresh Cymru lookup (IPv6 rejected)
- `parseOriginRecord(txt) (uint32, geofeed.CountryCode, error)` — one `origin.asn.cymru.com` TXT record. **Field 0 is a space-separated AS LIST, not one number**: a multi-origin prefix reads `"15169 43515 | 35.212.128.0/17 | US | arin | …"`, and parsing it whole used to fail the record and discard the country in field 2 — costing the annotate chain a hit and leaving `ASNFilter` fail-open, since a `Resolve` error keeps the IP. The first listed AS is taken, because the caller needs exactly one number for the `AS<n>.asn.cymru.com` name lookup and the record ranks nothing; the country is a property of the single registration and survives a list of any length. **The AS NAME does not**, and that is the residual cost: the name feeds the `{type: asn}` deny patterns, and they match the NAME STRING — so a pattern written for any AS but the first silently misses whenever the two names share no token it could have been written around (whether the operators are affiliated is a different question, and not the one measured). Beograd, RS`, RIPE orgs ORG-YA1-RIPE and ORG-TDB4-RIPE). It is still strictly better than the state it replaced, which missed every AS on such a prefix AND the country

## `internal/subscription`

`./internal/subscription/subscription.go`, `xray.go`, `vmess.go`, `ss.go`, `ssr.go`, `mieru.go`, `placeholder.go`

Subscription fetch, normalize (base64 → raw, Xray JSON → share links), and URI parsing. Lightweight node parser avoids `url.Parse` heap allocations. `Normalize` trims, converts an Xray config document when it sees one, uses a fast-path single-pass ASCII whitespace stripper, then attempts a tolerant base64 decode and converts again if the decoded body turns out to be JSON. That decode (`decodeBase64Tolerant`, shared with the vmess/ssr payload decoders) does at most ONE attempt: it picks the alphabet from structural cues — url-safe iff the payload holds `-` or `_`, padded iff its length is a multiple of four — because trying up to four alphabets in turn allocated a scratch buffer per failed attempt. Same accept set, same first-match precedence.

**Key types:**
- `Scheme` — strict URI scheme type alias
- `Node` — `Raw` + `Scheme` + `Name` + `Server` + `Port` + `FragmentIdx`

**Key functions:**
- `Load(ctx, url fetch.SubscriptionURL) ([]byte, error)` — fetch + normalize
- `Parse(body, yield) (rejected int)` — iterate lines via `ioutil.Lines`, parse URIs containing `://`; the return is how many URI-shaped lines `parseNode` refused (they never reach `yield`), which `preprocess.processBody` books as `Stats.Unsupported`
- `Normalize(body) []byte` — trim + Xray-JSON conversion + strip ASCII whitespace + base64 decode + URI detection. The JSON branch runs BEFORE the `://` fast path: real configs carry DoH server URLs and an observatory probe destination, so 4 of the 5 bodies measured contain `://` and would otherwise return untouched
- `convertXrayJSON(body) ([]byte, bool)` (`xray.go`) — renders the **vless** outbounds of an Xray config document (single object or the array a panel serves) as newline-joined share links, so `Parse`, `classify`, the geo pipeline, `Merge` and `rewrite` need no JSON awareness. False on anything that is not an Xray config or carries no vless outbound, which is what keeps every existing JSON-serving source classified exactly as before. Maps Xray's `raw` transport to `tcp` (mihomo's share-link handler has no `raw` case, so the name would reach `adapter.ParseProxy` as `network: "raw"`), brackets IPv6 authorities, and reads the ws `Host` header case-insensitively. `maxJSONOutbounds` (50 000) bounds the expansion, which `preprocess.processBody`'s node ceiling then sees post-expansion. Measured on one t.me/hiddifycode post: 158 vless outbounds across 5 JSON links against 8 nodes in the post's single URI-list link; 34 of its endpoints were absent from the live pool and 15 of those published (44%, against the pool's 0.35% end-to-end)
- `parseNode(line) (Node, bool)` — scheme → authority → host:port → fragment; the fragment is the FIRST `#` after the authority (later `#`s stay in the name); bracketed IPv6 hosts are returned without brackets, unbracketed multi-colon authorities are treated as a portless IPv6 host; a missing port defaults to `443`. The text before `://` must have the RFC 3986 scheme shape (`validScheme`: ALPHA then alnum/`+`/`-`/`.`) — the parser stays scheme-generic, but without that check an HTML error page or Clash YAML document parses as a healthy node list (`<a href="https` was a valid scheme). That generic walk is corrected or vetoed in exactly four places and nowhere else: `vmess` short-circuits before the authority walk into `parseVmess`, `ssr` discards the walk and returns from `parseSSR`, `ss` fixes up its server/port via `ssFields`, `mierus` takes its port from `mieruPort`; on top of that `http`/`https`/`socks`/`socks5`/`socks5h` are REJECTED without an explicit port (mihomo refuses a portless one, `convert/converter.go:543-546`, and accepting it published any bare web URL in a source body — a Telegram channel link, a panel notice — as a node). There is deliberately **no whitelist** of mihomo-known schemes: a scheme with no concrete reason to be rejected keeps the generic path. Allocation shape is therefore scheme-dependent — the generic path allocates nothing (`Server`/`Port`/`Name` are substrings of `Raw`), while vmess, legacy ss and ssr each decode one base64 buffer per node and return views into THAT buffer, which is the aliasing `stable.countryString` (`select.go`) reasons about when it renders `Entry.Country` from a `geofeed.CountryCode` VALUE instead of slicing whatever body resolved it
- `parseVmess(line, schemeEnd) (Node, bool)` — base64 JSON payload (`add`/`port`/`ps`); when `ps` is absent the display name falls back to the URI fragment, then to the server host. The three fields are read by `vmessFields`, a `json.Valid`-gated walk of the top-level object that hands back raw views into the decoded payload, NOT by unmarshalling it: the map form it replaced copied every field of a ~16-field document to read three, at a measured 55 allocations and 3050 B per node against a ~400 B line (`BenchmarkParse_Vmess`, 50 nodes: 1200 → 50 allocs/op, 46001 → 5604 B/op). `json.Valid` first is what keeps the accept set the map decode's, and key matching is BYTE-EXACT on purpose — mihomo's own vmess decode reads `values["add"]` off a map (`convert/converter.go:274`), so a struct decode's case-insensitive match would keep a node mihomo converts to nothing, costing a probe and a dead-cache entry. `decodeVmessJSON`'s map is still what `RewriteVmessName` round-trips through, and `vmess_internal_test.go` pins the two against each other
- `ssFields(authority, server, port)` / `decodeSSLegacy(authority)` (`ss.go`) — the PORT decides which `ss://` form this is, exactly as it does for mihomo (`convert/converter.go:396-407`): with one, the link is SIP002, keeps its host in the authority (`<b64userinfo>@host:port`) and takes the untouched generic result; without one, the whole authority is the pre-SIP002 form, base64 of `method:password@host:port`, with no host in the URI to read. The `@` cannot stand in for the port: `ss://<b64userinfo>@host` is SIP002-shaped but portless, mihomo drops it (it RawStd-decodes the bare host, which is not base64), and the generic path used to default such a line to 443 and publish, probe and dead-cache a node under a port it does not have. The reverse misread cannot happen — a legacy authority is base64, an alphabet holding no `:`, so it can never look portful. `decodeSSLegacy` accepts `base64.RawStdEncoding` and nothing else — deliberately narrower than `decodeBase64Tolerant`, because the shadowsocks spec writes the legacy form WITHOUT padding (<https://shadowsocks.org/doc/configs.html>) and mihomo decodes the authority with that alphabet alone (`convert/converter.go:398`), so a padded or url-safe payload would pass merge, spend a probe, yield no proxy and leave its `server:port` in the 2h dead cache. A payload that does not decode, carries no `@`, or yields an empty host is refused rather than handed to the resolver as a hostname, which would book an NXDOMAIN drop and lose the node on both endpoints. `splitHostPort` cuts at the LAST `@`, so a password containing one is safe
- `parseSSR(line, payload)` / `decodeSSR(payload)` / `ssrRemarks(query)` (`ssr.go`) — an `ssr://` payload is base64 of `host:port:protocol:method:obfs:password/?query`, so neither host, port nor display name (the base64 `remarks` query value) is readable from the URI, and the generic authority path would hand the blob to DNS as a hostname. `decodeSSR` mirrors mihomo (`convert/converter.go:483-504`) exactly — a `/?` split, exactly 6 colon-separated head fields, and a query `url.ParseQuery` accepts — because a node we keep but the prober cannot convert burns probe budget and can never be published, which is worse than an honest reject. On top of that `parseSSR` requires a dialable port (`portNumber`, a bare decimal in 1..65535): the port is the one head field `adapter.ParseProxy` decodes itself (`strconv.ParseInt` through the structure decoder), so a non-numeric one yields a mapping the prober cannot build — the node is merged, published, skipped behind a single "skipped unparsable proxies" log line and still booked into the dead cache as `host:<garbage>`. That window is deliberately stricter than the decode, which also takes `0`, `-1` and `70000` (`NewShadowSocksR` just `JoinHostPort`s the int, with no range check of its own, unlike mieru's `validateMieruOption`) — nothing can dial those, so the reject costs no reachable node. The query is first mapped onto the url-safe alphabet (`ssrURLSafeQuery`, as mihomo does in `convert/base64.go:36`) so a `+` inside a base64 value is not decoded to a space; a trailing `#name` is stripped before decoding. `FragmentIdx` keeps its generic meaning here — an ssr fragment is plain text in `Raw`, not part of the payload — but no output path uses it
- `PlaceholderNode(raw, server string) bool` (`placeholder.go`) — reports the panel stand-in a dead subscription serves, on two independent rules: an RFC 9562 §5.9 Nil UUID credential (all 32 hex digits, so a short all-zero password stays a password) that authenticates nobody, or a server that names the machine which would dial it — the unspecified address (`0.0.0.0`, `::`), the loopback `/8`, or `::1` — which reaches no remote however good its credential. The address half is worse than a dial failure: `connect(0.0.0.0:p)` reaches the loopback at `p`, so such a node on the service's own `:8080` passes `reachableTCP`'s bare `net.Dialer` and spends a full `URLTest` round on the worker itself. **Scope, decided from what a dialer does:** the whole loopback `/8` is IN, because the kernel routes all of it to `lo` (RFC 1122 host requirements), so a listener answers `127.0.0.53` as readily as `127.0.0.1` — and the measured corpus carries exactly such a node; `::ffff:`-mapped forms are IN, because a dialer unmaps them and connects over IPv4 (`netip.Addr.IsLoopback` unmaps before testing while `IsUnspecified` does not, which is why the differential test unmaps first); the rest of `0.0.0.0/8` is OUT, a destination a dialer refuses rather than sends home; a zone (`::1%lo`), a hex-written mapping (`::ffff:7f00:1`) and the deprecated `::0.0.0.0` are OUT by decision — no formatter emits them, a miss costs one probe slot, and the error this predicate must never make is deleting a working node. It lives here because BOTH consumers must agree on it — `classify.Body` refuses such a body a live verdict, `stable.Merge` refuses the node a probe slot — and the stable worker never calls `classify`, so a second copy would let a URL classify dead while its nodes kept being probed. Neither rule parses: `nilCredential` settles the ~15/16 of real UUIDs that cannot be Nil on the first byte, and the address rule requires the STRUCTURE of an address it accepts before reading any value — a word compare for the unspecified form, a `127.` prefix ahead of the only quad parse, an explicit group walk for the IPv6 spellings — so `netip.ParseAddr`, whose error is heap-boxed, is never reached. That is the repair for a charset prefilter that admitted strings the parser behind it rejects: measured 2026-08-14 with `BenchmarkPlaceholderNode` (medians of 5), `0`, `00.00.00.00` and `0.0.0.0.0` each cost 1 alloc / 48 B and 23-31 ns before and 0 allocs / ~8 ns after, with all 11 server shapes at 0 allocs and 7-14 ns/node. `TestPlaceholderNodeNeverOvercallsNetip` holds the recognizer to `netip`'s own verdict over 335,922 enumerated strings, and `TestPlaceholderNodeAllocatesNothing` runs the correctness table verbatim, so a shape added for correctness can no longer skip the allocation gate
- `RewriteSSRName(raw, newName) (string, bool)` — the ssr twin of `RewriteVmessName`: re-encodes the payload with `remarks` set to `newName`, emitting a **fragment-free** link in the unpadded url-safe alphabet, because mihomo base64-decodes EVERYTHING after `ssr://` — a `#fragment` included — and reads `remarks` with `RawURLEncoding`, so a fragment or a `=` pad (which `url.Values.Encode` escapes to `%3D`) makes the link unconvertible. Both `rewrite.NodeName` and `stable.relabelNode` route ssr through it. Sharing `decodeSSR` with `parseSSR` is what makes accepting a node and relabelling it ONE decision: it can no longer refuse a payload the parser let through
- `mieruPort(tail) (string, bool)` (`mieru.go`) — a `mierus://` link carries its port list in the query, never in the authority. Returns verbatim the first `port` value mihomo's adapter would actually **serve**: a decimal in 1..65535, or a `begin-end` range of two such with `begin <= end` (`adapter/outbound/mieru.go:301-324` — that adapter bound, not the looser converter, is the gate, because `adapter.ParseProxy` is what the prober feeds the converted map to), tested as written, before percent-decoding. The first *usable* port, not the first port: mihomo skips an unconvertible value and converts the rest (`convert/converter.go:662-683`), so taking it would book the node under a port nothing answers on, splitting it from its duplicates and poisoning a dead-cache key no probe can clear. Reports false — dropping the line — when there is no `port`, when no value is usable, or when the `port` and `protocol` value counts differ, which is when mihomo drops the whole link itself (`:656-660`)

**Uses:** `fetch`, `ioutil`
**Tags:** `subscription`, `uri`, `parse`, `node`, `normalize`, `base64`, `vless`, `trojan`

## `internal/rewrite`

`./internal/rewrite/rewrite.go`

Node output rewriting. Prepends the annotator's tag prefix (`[GEO:XX]`) before the node name. Strips existing known tags — deliberately a WIDER set than it writes, see `StripKnownTags`.

**Key functions:**
- `NodeName(b, node, tags string)` — write the node into a reusable `bytes.Buffer` with the already-formatted tag prefix (e.g. `"[GEO:AE]"`) folded into its name; empty `tags` reduces to a clean relabel; vmess folds into the base64 `ps` and ssr into the base64 `remarks` query value (`subscription.RewriteVmessName` / `RewriteSSRName`), every other scheme into the `#fragment`. For ssr the fragment path is not merely unused but corrupting — mihomo base64-decodes the appended `#name` along with the payload and the link becomes "format invalid" — and a payload neither rewriter can decode is written verbatim: unannotated beats mangled. The tag string is assembled by the preprocess annotator, and `[GEO:]` is the only prefix it can emit: the annotator has one rendering arm left (`config.TagGEO`), writing an ISO-3166-1 alpha-2 code or `??`. The stable worker prepends its own `"[SPD:<n>M] "` ahead of that
- `StripKnownTags(s) string` — remove the leading `[GEO:…]`, `[IP:…]`, `[ASN:…]`, `[SPD:…]`, `[OK]`, `[BAD]`, `[JUR:…]` tags (`isKnownTag`), skipping the whitespace between them. Only TWO of those are ever written by this service — `[GEO:]` from the one configured annotate tag (`config.TagGEO`) and `[SPD:]` from `stable.speedPrefix`; `[IP:…]`, `[ASN:…]`, `[OK]`, `[BAD]` and `[JUR:…]` are recognised so that an upstream-authored tag is stripped on relabel instead of accumulating in front of ours. `[IP:…]` and `[ASN:…]` are the arms that outlived their writers — both annotate tags were removed — and both have to stay: the scan consumes a CONTIGUOUS run and returns the remainder from the first tag it does not recognise, so without the ASN arm an upstream `[GEO:RU][ASN:SOME-AS, RU] Moscow` loses only its GEO tag and gets republished as `[GEO:xx] [ASN:SOME-AS, RU] Moscow`, carrying an AS attribution this service never made — and without the IP arm an upstream `[GEO:RU][IP:1.2.3.4] Moscow` republishes as `[GEO:xx] [IP:1.2.3.4] Moscow`, leaking an unverified address. Each arm needs a shape CONTAINING its own tag to show that: deleting the `IP:` arm leaves the ASN shape above stripping to `Moscow` unchanged, so testing that shape is what makes the arm look dead. `preprocess.TestAnnotateStripsUpstreamTagsItCannotWrite` is the ASN half of that guard

**Uses:** `subscription`
**Tags:** `rewrite`, `output`, `fragment`, `tag`, `geo-tag`, `ip-tag`

## `internal/geoblock`

`./internal/geoblock/store.go`

Persistent per-host geo-block list: node hosts that failed a through-node API reachability check (Gemini/Claude/ChatGPT), each with a TTL (default 30d). Backed by SQLite via the pure-Go `modernc.org/sqlite` driver (works under `CGO_ENABLED=0`/distroless). Reads are served from an in-memory cache (the filter hot path); the DB file is touched only on write/prune/load. Keys are **lowercased hosts** — a host is a DNS name, so two sources spelling the same node in different case must fold onto one entry, or the mixed-case duplicate of a blocked host is silently re-admitted every cycle. The `tidal` filter deliberately does NOT write here — see `internal/stable`.

**Key types:**
- `Store` — `Open(path, ttl)`, `Blocked(host) bool`, `Block(host) error`, `Prune() error`, `Count() int`, `Close() error`. `Block`/`Blocked` fold `host` to lower case, and so does `load`, which merges two legacy mixed-case rows for one host onto the later expiry (row-order independent); a stale mixed-case row is never refreshed again and ages out under the TTL. `Prune` is called once per stable cycle through `stable.Blocklist` (see `internal/stable`); `Open` also prunes, but that alone left expired rows and map entries in place for the whole uptime of a `restart: always` container.

**Uses:** `modernc.org/sqlite`
**Tags:** `geoblock`, `sqlite`, `ttl`, `blocklist`, `gemini`, `claude`, `chatgpt`

## `internal/preprocess`

`./internal/preprocess/processor.go`, `filters.go`

Core processing. Orchestrates subscription loading, DNS resolution, geofeed/ASN/allow-list filtering, and output rewriting per node.

**Key types:**
- `Processor` — geofeed country lookup (async background reload via `TryLock`) + optional dbip/registry `geoDB`s and a `cidrStore` (all lazily built, see below) + DNS resolver + sequential filter pipeline (no country cache, no groups map). The background swap is guarded: `loadEntries` (a field defaulting to `geofeed.LoadAll`, injectable in tests) reports how many sources failed, and `swapRefusal` keeps the live database when any source failed or the new set came back below `minSwapRatio` (half) of the current one — a truncated-but-200 body reports no error, so relative size is the only signal. A failed or refused reload leaves `loadedAt` on the last GOOD data and arms `retryAt` instead (`retryDelay`: 5 min doubling per consecutive failure, clamped to the refresh interval), so a transient outage is retried within minutes rather than after the full `refresh_interval` (24h in production), while a permanently dead source degrades to the normal cadence. `retryAt`/`reloadFailures` cross a config reload with the data they belong to (`GeoState`, `CIDRState`); without that the crawler's hourly `private.yaml` rewrite would reset the backoff before it ever grew.
- `Stats` — `Total` / `Kept` / `DNSDrop` / `GeoDrop` / `ASNDrop` / `CIDRDrop` / `GeoBlockDrop` / `IPv6Drop` / `Unsupported`. `Kept` plus every drop reason sums back to `Total` (`TestFilterStatsIdentityHoldsWithCIDRDrop` pins the allow-list into that identity, or a node it dropped would be invisible in `X-Preprocessor-Stats` and on the dashboard); `IPv6Drop` counts nodes whose server is a non-IPv4 literal (refused before any lookup — they used to be mis-booked as `DNSDrop`). `Unsupported` sits OUTSIDE that identity: it counts `://`-bearing input lines `subscription.Parse` refused, which never became nodes, so a body of pure junk still leaves `Total == 0` and fails the call
- `PipelineContext` — request-scoped state shared across filters (`Lookup`, `Allowed`, `Denied`, `Resolved`, `Scratch`, `Stats`, plus the unexported `sink`); `Scratch` is the per-node IP slice handed to filters (they compact in place), keeping the `Resolved` cache pristine across nodes sharing a server. `Lookup` is `Processor.countryChain`: the LOCAL country databases EVERY configured `GEO` entry's chain names, concatenated in written order and de-duplicated by first occurrence, first answer wins — not every database this process loaded (a chain naming only `dbip` leaves the geofeed out of the filter) and never `asn` or `cloudflare`, which are not local tables
- `nodeSink` — where a surviving node goes; `emit(ctx, node, ip)`. `bufferSink` renders the published text (the `\n` separator between nodes and the annotator call both live here; a nil annotator emits `node.Raw` verbatim), `sliceSink` appends `NodeResult`s. `processNode` therefore no longer knows whether it is producing a response body or a work list
- `NodeResult` — one node that survived the IP stage, unannotated: `Raw` (a CLONE — `subscription.Parse` hands out views into the source body, which dies with the call) and `IP`, the address the filters judged it by. Whatever tags are rendered later must describe that same address, never a second resolution of the hostname
- `Egress{IP, Country}` / `Valid()` — what a node reported about ITSELF through the `cloudflare` probe; the zero value means it was never measured (always, on `/`)
- `AnnotateRequest{Node, IP, Egress, Prefix}` — one node to annotate. The CALLER picks `IP` (the traced egress when there is one, the resolved address otherwise) — the annotator never branches on address provenance. `Prefix` is written ahead of the configured tags verbatim, for tags the caller renders itself (the worker's `[SPD:60M] `)
- `Annotator` — `Annotate(ctx, dst, scratch, req) geofeed.CountryCode`; appends one node line to `dst` (no trailing newline, never resets `dst`) and returns the country the GEO chain resolved (zero = nothing resolved it, or no GEO tag). The stable worker records that code as the node's country instead of re-parsing the rendered name
- `Filter` — interface for one IP-stage filter; `Process(ctx, ips, pctx)`
- `GeofeedFilter` — keeps IPs whose country `filter.Permits(pctx.Allowed, pctx.Denied, …)` accepts; a full allow set with an empty deny set makes it a no-op. An IP no database can place survives an exclusion and is dropped only by an allow-list. The name is historical: it judges against the whole `pctx.Lookup` chain, the same LOCAL databases the GEO annotation resolves against — every `GEO` entry's, not just the first — so a node is never dropped as unplaceable while carrying a tag a LOCAL database placed it with (`TestGeofeedFilterNeverDropsATagThatPlacesTheNode`). That is the whole promise, and the local scope is the load-bearing half: `asn` and `cloudflare` are outside the chain, so a node only Cymru or the egress probe can place is still geo-dropped while its own chain renders `[GEO:DE]`
- `ASNFilter` — drops IPs matching ASN deny patterns AND IPs whose Cymru-resolved country the same `filter.Permits` pair rejects (so country filtering works via the ASN provider without a geofeed stage)
- `CIDRFilter` — an ALLOW-list: it keeps the IPs inside the downloaded `cidrset.Set` and books one `CIDRDrop` per NODE when none is left, exactly as `GeofeedFilter` books `GeoDrop`. It reads nothing off the request — membership of the node's own address is the whole policy, so `/` and the worker get the same verdict and no query param can widen it. The set arrives through a getter, not a value, for the reason `geo.NewLookupProvider` takes one: the filter must follow the background refresh rather than pin the set it was built with. Because `processNode` stops at the first filter that empties the IP slice, a node is booked under exactly one reason and config order decides which — putting `cidr` first is what makes it the cheapest gate, one binary search ahead of every Cymru round trip
- `annotator` (`annotator.go`) — implements `Annotator`: builds the ordered `[GEO:…]` tag prefix for `req.IP`, then writes the relabeled node via `rewrite.NodeName`; nil when no tags are configured (annotation disabled, raw node emitted). Each GEO entry carries an ordered chain (`annotTag.chain` of `annotStep`, resolved against the map of providers the processor actually built — a referenced-but-missing name is logged and skipped, not panicked): the first step that answers wins; all-miss renders `[GEO:??]`, and `Annotate` returns the leftmost entry that actually RESOLVED (the zero code, never a rendered `??`). `annotTag.key` survives the one-tag world because `Annotate` guards on it (`if t.key != config.TagGEO { continue }`) and so renders nothing for a spec built in code with any other tag — dropping the guard would publish that entry's chain answer as a `[GEO:xx]` tag and return it as the node's country; `preprocess.TestAnnotatorRendersNothingForUnacceptedTag` is the only test that fails when it goes. A step with a **nil** `prov` is `cloudflare`: it is not a lookup, it repeats `req.Egress.Country` when `req.Egress.Valid()` and misses otherwise, so it is deliberately absent from the provider map (a name missing there is a wiring bug worth an Error log, and cloudflare would trip it on every processor build, `/` included). `req.IP` is what every chain resolves against, but no tag renders the address itself any more: the dotted-quad `writeIP` writer went with the `IP` tag, and `lookupASN` went with the `ASN` one
- `geoDB` — one downloadable in-memory IP→country database (dbip or registry) under the processor's mutex discipline (`mu` guards lookup/loadedAt/retryAt, `reloadMu` serializes refreshes). Startup: a preloaded `GeoState` (reload carry-over) is adopted whole — lookup, load time AND retry schedule, so a mirror that is currently failing keeps its backoff instead of being re-downloaded on the first request after every reload; otherwise the initial load runs inline but a failure only WARNs and starts with an empty lookup — startup must never depend on a third-party database mirror, the annotate chain just degrades. A failed or partial initial load arms `retryAt` so the next attempt lands in minutes instead of a whole interval. Refresh: opportunistic background reload on the request path (`maybeRefreshDatabases` → `TryLock`, same trigger point as the geofeed refresh), running the same `swapRefusal` + `retryDelay` guards as the geofeed path, so a dead RIR can neither shrink the live database nor pin it for a day.
- `cidrStore` — the downloaded cidr allow-list, mirroring `geoDB` field for field (`mu` guards set/loadedAt/retryAt, `reloadMu` serializes refreshes; `maybeRefresh` → `TryLock` on the request path; `staleLocked`, `scheduleRetryLocked`, `retryDelay` backoff, last-good kept on failure) and differing, once built, in exactly three places — its build TRIGGER is a fourth divergence and sits under `Options`/`providerNeeds` below, which is why README's count of three covers a different three. **Startup is FAIL-CLOSED**: where an empty `geoDB` only WARNs, `newCIDRStore` returns `errEmptyCIDRSet` and `NewProcessor` fails, because an allow-list nobody is inside is not a milder filter but the opposite one — the instance would publish an empty list rather than a degraded one, and a reload hitting that error keeps the previous processor. **The swap guard compares COVERED ADDRESSES**, `swapRefusalSize(s.set.Covered(), next.Covered(), failed)`, never `Len()` — see `cidrset.Covered` for why the range count is the wrong unit, and `swapRefusalSize` for why both sides are `uint64` where the geo databases count in `int`. A refusal logs both numbers (`loaded`/`current` ranges and `loaded_covered`/`current_covered`) so an operator can tell a shrink from a reshape. **`snapshot()` is read per NODE**, where the sibling tables are snapshotted once per request into `pctx.Lookup`: the filter holds the getter and calls it for every node it judges. That is deliberate and the WHY sits on the method — the extra RLock pair is free on the single-goroutine `/` path and measured immaterial against a concurrent worker cycle, and a list that swaps mid-request is still one the operator published, so either verdict is valid
- `Blocklist` — interface `Blocked(host string) bool` (satisfied by `*geoblock.Store`); when set, `processNode` drops nodes whose `Server` is currently geo-blocked (`GeoBlockDrop`) before DNS resolution, on both `/` and the worker. Casing is the store's problem, not this call's: it folds the host to lower case, so a source spelling a blocked node differently is still dropped
- `Options` — configuration struct for `NewProcessor` (`GeofeedSources`, `RefreshInterval`, `DNSTimeout`, `DNSAddress`, `DNSCacheTTL`, `DNSCacheNegativeTTL`, `FetchTimeout`, `ASNTimeout`, `ASNCacheTTL`, `IPFilters []config.IPFilterSpec`, `Annotate []config.AnnotateSpec`, `DBIP config.DBIPConfig`, `Registry config.RegistryConfig`, `Blocklist`, plus the `Preloaded*` carry-over fields and the unexported `cidrLoad`). `IPFilters` drives the filter chain; `Annotate` builds the annotator (empty → the node's original name passes through). `providerNeeds` decides which geo backends are lazily built: the ASN resolver when any IP filter or annotate chain needs it (asn filter, `country` provider `asn`, or `asn` in a chain), the dbip/registry `geoDB`s only when an annotate chain names them. The `cidrStore` is outside `providerNeeds` because its trigger is not a provider reference but the filter itself: `cidrSpec(opts.IPFilters)` finds the one `cidr` entry config allows, and the filter and the download are the same decision. `cidrLoad` is the test seam for it — the initial load runs INLINE in `NewProcessor`, so without an injectable loader every processor test would reach the network.
- `FilterRequest` — request struct for `Filter` (`SubscriptionURL fetch.SubscriptionURL`, `AllowedCountries filter.CountrySet`, `DeniedCountries filter.CountrySet`, `Body []byte`). `AllowedCountries` must be non-empty (`All()` when the caller asked for no allow-list) or `Filter` errors; `DeniedCountries` carries `exclude_countries`/`exclude_groups`. When `Body` is non-empty the payload is filtered directly — normalized with the same `subscription.Normalize` (base64-tolerant) used for fetched bodies, **skipping `subscription.Load`/HTTP fetch** — and takes precedence over `SubscriptionURL`; the log context labels it `inline`. URL-source behavior is unchanged.

**Key functions:**
- `NewProcessor(ctx, logger, opts Options) (*Processor, error)` — `initialGeofeedState` first (or `opts.PreloadedGeofeed` when set; a geofeed load failure IS fatal, unlike the geoDBs), then the geoDBs and ASN resolver per `providerNeeds` (reusing `opts.PreloadedASN` / `opts.PreloadedResolver` when the reloader carried them), then the `cidrStore` when `IPFilters` holds a `cidr` spec — that one is fatal both when the download errors and when it yields an EMPTY set — then the filter chain, then the annotator, handed only the providers actually built
- `(*Processor).Filter(ctx, b, req FilterRequest) (Stats, error)` — main pipeline writing into caller-owned `bytes.Buffer`, annotated inline (`/` has no post-probe stage to annotate in); a cancelled request returns `ctx.Err()` instead of a truncated list. Inline (`req.Body`) requests skip the fetch entirely and normalize the body in-process.
- `(*Processor).FilterNodes(ctx, req FilterRequest) ([]NodeResult, Stats, error)` — the SAME pipeline (`filterInto`, one shared body: same validation, same `Stats`, same log line, same `ErrTooManyNodes` / "no supported URI nodes found") behind the structural sink and with **no** annotation. The `/stable.txt` worker takes this path so the tags can be built once at the end of the cycle, out of what the probes learned
- `(*Processor).Annotator() Annotator` — the tag renderer, or an explicitly nil interface when `annotate` is empty (a `*annotator` handed out through the interface would read as non-nil to a caller branching on it)
- `(*Processor).GeofeedState() GeoState` — returns the lookup, its load time and the retry schedule in flight as one snapshot under the read lock; used by the reloader to carry geofeed state across config reloads when sources are unchanged (the underlying `loadedAt`/`retryAt`/`refreshInterval` fields are unexported; `shouldReloadGeofeedLocked` requires `p.mu`)
- `(*Processor).DBIPState() / RegistryState() GeoState` — same carry-over accessors for the downloadable databases (the zero `GeoState` when the provider was not built in this processor)
- `(*Processor).CIDRState() CIDRState` — the same carry-over accessor for the allow-list (the zero `CIDRState` when no `cidr` filter was configured); `newCIDRStore` adopts a preloaded state whole and tells it apart from "nothing carried" by `Set.Len() > 0`, which is unambiguous precisely because a live processor can never hold an empty set
- `(*Processor).ResolverState() *resolver.Resolver` / `(*Processor).ASNState() *asn.Resolver` — hand the live resolvers, and with them their warm caches, to the next processor across a reload; `ASNState` is nil when no filter or annotate chain needed ASN data
- `(*Processor).countryChain(ctx) geofeed.CountryLookup` — the lookup the country filter judges with: the local databases EVERY `GEO` annotate entry's chain names, concatenated in written order and de-duplicated by first occurrence (`chainLookup`, first non-zero answer wins; `countryChainOrder` derives the order once in `NewProcessor`, and dedup bounds it at the three local providers however many entries are written, so the per-request `chainLookup` cannot grow). The filter used to see the geofeed alone while the GEO tag resolved through the whole annotate chain, so a node dbip places in DE was geo-dropped as unplaceable while its tag said `[GEO:DE]`; the FIRST repair hardcoded geofeed → dbip → registry, which brought the divergence back for any operator who ordered the chain differently; the SECOND read the order off the config but stopped at the first `GEO` entry, which brought it back again for anyone who split a chain over entries, inverting BOTH verdicts — `countries=DE` dropped the node, `exclude_countries=DE` kept it and published `[GEO:??][GEO:DE]`. Concatenating every entry is the third. The `asn` provider stays out — it is a per-IP Cymru round trip, and `{type: country, provider: asn}` already exposes it explicitly. `cloudflare` stays out for a harder reason: it is not a lookup at all, it answers with what a node reported through ITS OWN proxy, and the IP stage runs before any proxy exists — so `{type: country}` remains offline and a `GEO` chain led by `cloudflare` still filters on the local databases behind it. A geofeed-only chain, an asn-only chain and a config with no `GEO` entry all collapse to the geofeed lookup alone
- `(*Processor).resolveNode(ctx, server, pctx) (ips []netip.Addr, supported bool)` — resolve once per request/hostname and copy resolver results into request-local storage. `supported=false` means the server is an IP literal that is not IPv4; the caller books `IPv6Drop`, not `DNSDrop`, because nothing was ever looked up
- `buildFilters(specs []config.IPFilterSpec, asnR *asn.Resolver, cidrSet func() cidrset.Set) ([]Filter, error)` — construct the IP-stage chain in config order from the parsed specs (country→geofeed/ASN provider, asn→compiled deny patterns + ASN-country, cidr→`NewCIDRFilter(cidrSet)`). No implicit geofeed force-append: country filtering only happens when a `country` filter is configured. A `cidr` spec with a nil `cidrSet` is `errNoCIDRSet`, which the one current caller cannot reach — `NewProcessor` passes a non-nil getter exactly when a cidr spec exists, which is exactly when this arm fires. It is structural insurance rather than a live path: a SECOND caller that got the wiring wrong fails `NewProcessor` instead of panicking on a nil getter once per request. Enforcement of the per-request `AllowedCountries`/`DeniedCountries` (from `countries`/`groups` and `exclude_*` on `/`, or `All()` + the config excludes for the worker) happens inside the country filter.
- `FormatStats(stats) string` — `done: total=N kept=N …`
- `(*Processor).processBody(ctx, body, pctx) error` — parse + per-node pipeline. Adds `subscription.Parse`'s rejected-line count to `Stats.Unsupported`. Rejects a body over `maxSubscriptionNodes` (50 000) with `ErrTooManyNodes` BEFORE the first lookup: resolution is serial with a 5s per-hostname timeout, so a 10 MiB body of ~380k minimal URIs would otherwise be hours of DNS. The ceiling is a DoS bound, not a quality filter — at its first value of 20 000 it rejected a configured 33.4k-node aggregator source outright, which is why it has to clear the largest source an operator would legitimately configure. One vectorized newline count serves both that ceiling and the survivor slice: `Parse` yields at most one node per line, so only a body clearing the bound pays for the exact `countNodes` parse (keeping the check off the hot path), and a sink implementing `sizer` is handed `min(lines, maxNodeHint)` to reserve. `sliceSink` is the only one that does — `bufferSink` renders into a buffer its caller owns and sizes. `maxNodeHint` (16384) caps the reservation because the line count is an upper bound and a body of junk lines yields no nodes at all; it clears the largest configured source (11k nodes in one 3.06 MB body) and bounds a junk body at one 640 KB buffer. Growing into the slice instead cost a measured 7.6 MB per cycle across the 157-source corpus, and `BenchmarkProcessBodySlice_LargestSource` 4307267 → 2906806 B/op. Callers on `/` map the sentinel to `413`
- `swapRefusalSize(currentSize, loadedSize uint64, failed int) string` — the size-only refusal rule shared by the geo databases and the allow-list: nothing to protect when the current size is 0, "partial load" when any source failed, "catastrophic shrink" below `minSwapRatio`. **The unit is the caller's** — ranges for the geo databases, covered ADDRESSES for the cidr store — and the sizes are `uint64` for that second unit's sake: `0.0.0.0/0` admits 2^32 addresses, which an `int` does not hold on a 32-bit build, and narrowing it to 0 there would silently disable the guard for the widest list there is. The geo callers widen their `int` range counts on the way in, passing 0 for "unknown, nothing to protect"; `swapRefusal` is that thin `geofeed.CountryLookup` wrapper, measuring with `lookupLen`
- `maybeRefreshDatabases(ctx)` — the request-path refresh trigger for every downloaded table the processor holds: dbip, registry and the cidr allow-list. Renamed from `maybeRefreshGeoDBs` when the allow-list joined, since it is not a geo database
- `initialGeofeedState(ctx, initLog, opts) (GeoState, error)` — the geofeed half of the startup load, extracted out of `NewProcessor` so the three inline initialisations (geofeed, geoDBs, allow-list) read as three calls rather than one 60-line prologue

**Options fields added for hot-reload:**
- `GeoState{Lookup, LoadedAt, RetryAt, Failures}` — the carry-over unit for one country database. The four values are one type because they are only correct together: carrying the data while dropping the retry schedule makes a source whose last reload failed read as permanently stale (`LoadedAt` marks the last GOOD data), so the first request after every reload re-downloads it — hourly, given the crawler's `private.yaml` rewrites
- `PreloadedGeofeed GeoState` — when `Lookup` is non-nil, `NewProcessor` skips the initial geofeed fetch and adopts the whole state, retry schedule included
- `PreloadedDBIP` / `PreloadedRegistry GeoState` — same pattern for the dbip/registry databases; used only when the matching provider is referenced by `Annotate`
- `PreloadedCIDR CIDRState` — the allow-list's carry-over (`CIDRState{Set, LoadedAt, RetryAt, Failures}`, one type for `GeoState`'s reason); the reloader sets it when `!config.CIDRFiltersChanged`, and `newCIDRStore` adopting it is what keeps a reload from re-downloading and re-merging the whole list
- `PreloadedResolver *resolver.Resolver` / `PreloadedASN *asn.Resolver` — carry the DNS and Cymru caches across a reload instead of rebuilding them cold. The reloader sets them only when the whole `resolver` / `geo.asn` block is unchanged, because both bake their timeouts and TTLs in at construction; a carried `PreloadedASN` is dropped when nothing references ASN data

## `internal/server`

`./internal/server/server.go`, `holder.go`

HTTP layer using Fiber (`ReadTimeout` 30s, keepalive disabled). Routes: `GET /healthz` → `ok`, `GET /` → preprocess subscription, `GET /stable.txt` → latest stability-tested node list. The active `Processor` and groups map are held in an atomic `Holder` so the reloader can swap them without restarting the server.

The root handler now accepts:
- `subscription_url` (required)
- `countries` / `groups` — additive allowed countries
- `exclude_countries` / `exclude_groups` — a deny-list of countries to drop

`countries`/`groups` and `exclude_*` are enforced separately: the first is an allow-list, the second a deny-list applied to the resolved country. An IP no geo source can place passes the deny-list (it is in no excluded country) but fails a non-empty allow-list. Any token the server cannot resolve — an unknown group name, or a country that is not a 2-letter code — is a `400` naming the offending token, never a silently narrowed filter. If `countries`/`groups` are present but produce an empty set, or the exclusions cover every allowed country, the request also returns `400`.

`GET /stable.txt` serves the newest `stable.Snapshot` payload (plain-text URI list) with an `X-Stable-Stats` header (`updated=<RFC3339> sources=<ok>/<total> merged=<n> tested=<n> kept=<n>`). It returns `503 stable list not ready` until a list exists — the first successful check cycle, or, with `subscriptions.snapshot_path` configured, the snapshot `app.Run` restored at startup. A restored list keeps its ORIGINAL `updated=`, so its age is visible rather than reset by the restart.

**Key types:**
- `Filterer` — interface `Filter(ctx, b, req preprocess.FilterRequest) (Stats, error)`
- `Snapshot` — `Svc Filterer` + `Worker stable.Filterer` + `Groups map[string][]string`; the immutable value swapped atomically on reload. Both interfaces hold the SAME `*preprocess.Processor`: `Svc` is the narrow one `GET /` needs, `Worker` the wider one the `/stable.txt` cycle needs (`FilterNodes` + `Annotator`). Two fields rather than one wide interface plus a type assertion, so a snapshot that forgot the worker's half is a compile error instead of a runtime skip
- `Holder` — wraps `atomic.Pointer[Snapshot]`; safe for concurrent reads and single-writer stores
- `Server` — `listen` + `fiber.App`

**Key functions:**
- `NewHolder(initial *Snapshot) *Holder` — create a Holder seeded with the startup snapshot
- `(*Holder).Load() *Snapshot` — atomic load of the current snapshot
- `(*Holder).Store(s *Snapshot)` — atomic store of a new snapshot (called by reloader)
- `New(logger zerolog.Logger, listen string, holder *Holder, stableHolder *stable.Holder) *Server` — wires Fiber, logging, and the filter handler; reads `Holder` on every request so reloads are picked up without restart
- `newIndexHandler(holder *Holder) fiber.Handler` — root handler: loads snapshot, validates URL, builds the allowed/denied sets (rejecting unresolvable tokens with `400`), then calls `Filterer` under an explicit `indexRequestTimeout` (60s) deadline derived from `c.Context()` — fasthttp's request context has no deadline and never cancels on client disconnect. `preprocess.ErrTooManyNodes` maps to `413`, a deadline to `504`, anything else to a generic `502`
- `newStableHandler(holder *stable.Holder) fiber.Handler` — serves the stable payload or `503` before the first cycle; with `subscriptions.snapshot_path` set, `app.Run` has already stored the previous run's list into the holder, so the `503` window shrinks to a genuinely cold start
- `buildCountrySet(rawCountries, rawGroups, groupsMap) (CountrySet, []string)` — HTTP-layer group expansion (used for both the allowed and the denied set); the second return lists tokens it could not resolve, which the handler turns into a `400`
- `newRecoveryMiddleware(logger) fiber.Handler` — recovers a handler panic into a `500` (panic value + stack logged at error level, never sent to the client). Neither fiber nor fasthttp recovers, and a panic would take the in-memory stable list down with the process. Registered inside the logging middleware so the request still gets an access-log line
- `redactSubscriptionURL(raw) string` — `host#<12 hex of sha256>` for the access log: subscription links are capability URLs, so the verbatim value would put a bearer token in `docker logs`
- `(*Server).Listen() error`
- `(*Server).Shutdown(ctx) error`
- `(*Server).TestApp() *fiber.App` — for test usage

**Uses:** `fetch`, `filter`, `preprocess`, `stable`, `fiber`
**Tags:** `http`, `fiber`, `api`, `handler`, `server`, `healthz`, `atomic-swap`, `hot-reload`

## `internal/stable`

`./internal/stable/stable.go`, `snapshot.go`, `merge.go`, `select.go`, `report.go`, `prober.go`, `prober_api.go`, `prober_gemini.go`, `prober_claude.go`, `prober_chatgpt.go`, `prober_tidal.go`, `prober_trace.go`, `prober_bandwidth.go`, `nodefilter.go`, `label.go`, `checker.go`, `controller.go`, `progress.go`, `deadset.go`

Background worker that produces a stability-tested subscription list. Every `subscriptions.interval` it fetches each configured source through the geo/ASN pipeline (`Filterer.FilterNodes`, which annotates nothing), merges the results into one deduplicated relabeled URI list, TCP-dials each distinct server endpoint of an allow-listed TCP type once and spends the embedded mihomo library's `URLTest` (HEAD requests, `check.rounds` rounds) only on what answered — `hysteria`/`hysteria2`/`tuic`/`mieru` reach their servers over UDP and vless with `network=xhttp` plus `alpn` exactly `[h3]` over QUIC, so those are never dialled and go straight to the URL test, keeps only nodes within `check.max_fail`/`check.max_avg_ms`, then runs the configured **through-node filters** on each surviving node (a real API `GET` whose body is classified — the check mihomo's HEAD-only `URLTest` cannot do): every one of them is a **gate** (Gemini/Claude/ChatGPT reachability, Tidal availability, bandwidth) that drops what it refuses. Only then, on the final survivor set, does it ask each node where its traffic leaves from (`TraceCheck`) and build the published names ONCE, in `BuildPayload`. It records geo-blocked node hosts in the `geoblock` store (TTL) and drops them, and atomically publishes the rest for `GET /stable.txt`. Every failure mode (all sources down, zero parsable nodes, prober error, zero survivors) keeps the previous snapshot.

**Key types:**
- `Stats` — `SourcesOK/SourcesTotal/Merged/Tested/Kept` counters for the `X-Stable-Stats` header. The `json` tags on it are the persisted snapshot's `stats` object, so renaming a field renames a key in files older processes wrote
- `Snapshot` — immutable `Payload []byte` + `UpdatedAt` + `Stats`; persisted verbatim by `SaveSnapshot` when `subscriptions.snapshot_path` is set
- `Holder` — `atomic.Pointer[Snapshot]`; `Load()` returns nil before the first successful cycle, or before a restored snapshot is stored into it. It stays a bare pointer: persistence is `app.Run`'s and the `Checker`'s concern, so nothing that reads the list has to know a file exists
- `SourceBody` / `Entry` — merge input (source name + the `[]preprocess.NodeResult` its IP stage kept) and output. `Entry.Label` is the unique `<source>-NNN` string, and the key EVERY proxy↔entry map in this package uses (see `entryLabel`); `Entry.Raw` is the node line carrying that clean name — the one that is probed AND the one the publication annotates, since nothing is tagged before the cycle ends; `Addr` is the lowercased server:port dead-cache key; `IP` is the address the IP-filters judged, carried forward so the offline GEO chain annotates the SAME address the filter judged (the worker never resolves a hostname twice) — it feeds `step.prov.Lookup()`, so it stays load-bearing for the GEO tag even though no tag prints the address itself; `Country` is filled ONLY at publication, from what the GEO chain returned — `"??"` when nothing resolved it, `""` when annotation is off or the line did not parse.
- `ProbeResult` / `Survivor` — per-node probe aggregate and selected node with mean delay; `ProbeResult.Stage` is a `ProbeStage` naming how far the probe got (`condemned`/`connect`/`fetch`/`passed`, ordered by progress so the port fold keeps the furthest), which is the only thing separating a node the pre-check refused from one whose tunnel came up and failed the GET; `Survivor.Mbps` holds the bandwidth filter's measured speed (0 when the filter is off) and `Survivor.Egress` (`preprocess.Egress`) what the node reported about itself through `TraceCheck` (zero when no trace ran or none answered)
- `Survivor.MeanMs` — the probe's mean delay, and read THREE times: `SelectSurvivors` gates on it against `check.max_avg_ms`, sorts the published list by it, and `keptLatencies` (`checker.go`) collects it into `CycleReport.KeptLatenciesMs` for the `stable_kept_latency_ms` histogram. Until that metric it reached no log and no metric at all, so the threshold that decides the list's size had no observable to tune against — the sibling `Survivor.Mbps`, which gates nothing by default, had one
- `Filterer` — the worker's half of `*preprocess.Processor` (`FilterNodes` + `Annotator`), declared locally to avoid an import cycle; `server.Snapshot.Worker` holds the same processor under this interface while `Snapshot.Svc` serves `GET /` through the narrower `server.Filterer`
- `Prober` — `Probe(ctx, payload) (map[string]ProbeResult, error)`; implemented by `MihomoProber`. The map is keyed by **entry label**, not by mihomo proxy name, and holds one entry per label for every node that reached the prober — `Successes: 0` when every port failed, so `Successes == 0` is what marks a node dead (`recordDead` reads the field, because keying it on presence emptied the dead cache the moment the map became fully populated). It still ALSO blocks on absence, and that clause is load-bearing rather than vestigial — but not because a prober returns an empty map (`parseProxies` errors instead, and `RunOnce` aborts before `recordDead`). The reachable case is an entry whose proxies survived `Merge` and were then dropped by `convert.ConvertsV2Ray` or `adapter.ParseProxy`: `foldProbeResults` never names it, so only `!ok` blocks it. Before any round, `filterReachable` TCP-dials each distinct server endpoint once and drops what accepts nothing, so a black-holed endpoint costs `check.timeout` (`precheckAttempts` attempts sharing one round's budget, `precheckDialBudget`) instead of `check.rounds` × `check.timeout`, and one refusing a SYN costs microseconds; it dials at its own concurrency because `check.concurrency` is pinned per instance (16 in `config/`, 32 in `config-vassago/`) to keep contention out of the latency `max_avg_ms` gates on, and this verdict is one bit no gate reads. The dial is only sound for adapters mihomo reaches over TCP, so `dialsServerOverTCP` is an allow-list that FAILS OPEN: `hysteria2`/`tuic`/`mieru` reach their server over UDP and an unknown type must lose the speedup, never the node. A `mierus://` entry arrives as several proxies (one per configured port) that all fold onto one label, and `foldProbeResults` keeps the BEST of them (`betterProbe`: more successful rounds, lower mean, then furthest stage) — best-of, never a sum, since mieru dials one of its ports, and adding N ports' rounds together would let `Successes` exceed `check.rounds` and walk straight through `SelectSurvivors`' `maxFail` gate. Iterating the proxies rather than the accumulator map is what makes a tie resolve in payload order instead of by map-iteration chance
- `Blocklist` — `Block(host)` + `Prune()`, the through-node geo-block store (`*geoblock.Store`, SQLite/30d, keyed by lowercased host). `DeadCache` — `Blocked(key)/Block(key)/Prune()`, the dead-node cache; satisfied by `*DeadSet` (in-memory, not persisted — dead nodes are cheap to re-probe after a restart). Both carry `Prune` because the `Checker` sweeps every TTL cache it wrote to once per cycle (`pruneCaches`); the geoblock store used to be swept only inside `geoblock.Open`, so on a long-lived container it grew for the whole uptime.
- `APIOutcome` — per-node through-node API result (`Server`/`Reachable`/`Blocked`), shared by the gemini/claude/chatgpt/tidal checks
- `Checker` — the periodic worker loop, holding the injected `Blocklist`/`DeadCache` and nothing else cache-shaped. `filterDead` skips a merged node for exactly one reason: the dead cache holds a recent failed probe for it. A through-node verdict is NOT remembered here — it used to be, in a 6h per-filter "reject cache", which the round-4 rule that only a store-backed check may seed it made redundant: the checks still allowed to seed it (gemini/claude/chatgpt) write `store.Block(o.Server)` on the same line, and that entry is strictly stronger in every dimension — `preprocess.processNode` drops the host as `GeoBlockDrop` a whole stage earlier (before `Merge` even builds the `Entry`), for 720h instead of 6h, keyed by host rather than `host:port`, and across restarts. The reject branch could therefore essentially never fire, so it, `rejectKey`, `recordRejects`, `NodeFilter.active()`, `NodeFilterParams` and `DeadSet.Reset` are all gone; the one case the cache still caught — a second source spelling the host in different case — is now closed inside `geoblock` by folding the key to lower case. `recordDead` writes that cache on `Successes == 0` rather than on absence from the probe map: a label reads zero only when EVERY port failed (`foldProbeResults` folds best-of-ports), so the two coincide while the map carries successes only, and an absence test would silently stop blocking anything the moment it carries an entry per label — emptying the cache and putting the ~74% pre-probe skip back on the probe.
- `CheckerSpec` — the config-derived half of a `Checker` (`Sources`, `Denied`, `Interval`, `Rounds`, `MaxFail`, `MaxAvgMs`, `SourceTimeout`, `Prober`, `Filters`, `Trace`), held in an `atomic.Pointer` and read once per cycle so a reload configures the NEXT cycle instead of rewriting the running one. `Denied` is the config-level country deny-set; the worker never imposes an allow-list, so it sends `filter.All()` as `AllowedCountries`. `Trace` comes from `cfg.AnnotateUsesProvider(config.ProviderCloudflare)` — the egress probe costs one request through every survivor, so it only runs when a tag can render its answer. Nothing here needs to be diffed on reload: `Reconfigure` just swaps the pointer, because no cycle-crossing state is derived from these params any more.
- `Controller` — owns the single `Checker`: starts it on first enable, reconfigures it in place on every later reload, stops it only on shutdown or an emptied source list
- `CycleReport` / `SourceReport` / `FilterReport` / `TraceReport` / `GeminiReport` — per-cycle accounting (aggregate counts + per-source preprocess drops + per-filter in/kept/dropped-by-reason + kept-node speeds and mean latencies (`KeptSpeeds` / `KeptLatenciesMs`) + duration + `ProbeStages` + the trace stage + the gemini gate's self-account), assembled by `RunOnce` from data otherwise only logged. `SourceReport` mirrors `preprocess.Stats` field for field (`DNSDrop`/`GeoDrop`/`CIDRDrop`/`ASNDrop`/`GeoBlockDrop`/`IPv6Drop`/`Unsupported`), so a drop reason added to the IP stage has to be copied in `fetchSources` or it reaches neither the dashboard nor this report. `TraceReport` is `Answered`/`Unanswered`/`Moved`, where `Moved` counts published countries that differ from what the offline chain gives for the RESOLVED address — the number the trace exists to justify, bounded in trustworthiness by the answered share
- `CyclePhases` — `CycleReport.Phases`, the six stage durations `RunOnce` times at its own boundaries: `Fetch` (`fetchSources`, so downloads AND the per-node IP stage), `Merge`, `DeadFilter`, `Probe`, `Egress` (`filterAndMeasureEgress` — the through-node filters plus the `cdn-cgi/trace` measurement) and `Publish` (`BuildPayload` + `movedCount` + `c.publish`: the atomic swap, `SaveSnapshot` and the published-cycle log). `Probe` and `Egress` are deliberately NOT one phase: both do per-node network work, `Probe` covers payload parsing and the reachability pre-check as well as the rounds, so `check.timeout` × `check.rounds` bounds only its last part, while `Egress` runs on each filter's own timeout, and folding them hides the one number a 20-minute cycle is being optimised against. They sum to LESS than `Duration` — `recordDead`, `SelectSurvivors`, `pruneCaches` and the report assembly sit between phases and belong to none — so the residue is real overhead rather than a rounding error. A cycle that ABORTS contributes no phases at all: every abort path takes `reportError` → `ObserveError`, which leaves the last report in place, so `stable_cycle_phase_duration_seconds` keeps describing the last cycle that PUBLISHED, exactly like `stable_cycle_duration_seconds` and every other gauge fed from it
- `CycleReport.ProbeStages map[ProbeStage]int` — the probed set split by how far each probe got, folded by `probeStages` (`checker.go`) and rendered as `stable_probe_outcome_nodes{stage=…}`. It walks the PROBED ENTRIES, not the result map, so a label the prober never named (its proxies did not parse) counts as `StageUnknown` instead of vanishing and the counts sum to `Probed` — the ratio the panel divides by `stable_probed_nodes` has to close, or the stack silently understates. `stage="condemned"` is the reachability pre-check's yield and the number that decides what a probe-time gate can save — but only while `stable_precheck_trusted` is 1, since a tripped breaker discards the verdict and condemns nobody, and an unresolvable name is no longer condemned at all; `stage="connect"` merges transport and crypto deliberately, because mihomo's vless adapter renders its dial error with `%s` (`adapter/outbound/vless.go:312`) and vless is ~80% of the pool, so an `errors.As` split would resolve for `trojan` and never for `vless` — the same failure reading as two different stages per protocol is worse than one honest class. Counts NODES, folded best-of-ports, so it cannot express what share of ATTEMPTS burned the full `check.timeout`
- `GeminiReport{State GeminiGateState, Checks, Unverified int}` — how much of the gemini gate's verdict the cycle actually got. `Unverified` counts responses that arrived BEFORE the location check (`geminiInconclusive`); those nodes are **KEPT and published**, which is exactly why this is not a `FilterReport.Dropped` key — that map renders as `stable_filter_dropped_nodes{reason=…}`, the shape the trace's `corrected`/`unanswered` already got wrong once (shipped by `b545d0a`, corrected in `e554307`). `Checks` is the gate's own denominator: classifier calls, so one per PROXY that answered, neither the node count nor `FilterReport.In`. `GeminiGateState` is `Absent` (zero value — no gemini filter ran, nothing is rendered) / `Skipped` (configured but keyless: it checked nothing and passed every survivor through) / `Ran`, so a dead gate cannot read as a clean one
- `PrecheckReport{State PrecheckState, Dialled, Refused, Unresolved int}` — `CycleReport.Precheck`, what the TCP reachability pre-check did, in the same shape as `GeminiReport` and for the same reason: a gate that is OFF must not read like a gate that is FINE. `PrecheckState` is `Absent` (zero value — the cycle's `Prober` runs no pre-check, or `Probe` failed before reaching it; `writePrecheck` then emits NOTHING) / `Tripped` (the breaker fired, so the verdict was discarded and everything was URL-tested — `stable_precheck_refused_endpoints` is then the only surviving trace of what was thrown away) / `Ran`. `Probe` zeroes the field on entry so a failed cycle never reports the previous one's numbers. The counts are **ENDPOINTS** (distinct `server:port`), never nodes, so they deliberately do NOT match `stage="condemned"`: a multi-port `mierus://` node is several endpoints and a UDP-dialling adapter is none. `MihomoProber` exposes it through the optional `precheckReporter` capability that `RunOnce` type-asserts exactly like `traceChecker`, rather than a third `Probe` return value. Rendered as `stable_precheck_{trusted,dialled_endpoints,refused_endpoints,unresolved_endpoints}` (panel 19). Nothing here rides `FilterReport.Dropped` — the pre-check is not a filter
- `Reporter` — nil-safe metrics sink: `Observe(CycleReport)` on a published cycle, `ObserveError()` on any abort/no-op; `*metrics.Metrics` implements it

**Key functions:**
- `Merge(bodies []SourceBody) []Entry` — parse each kept node line on its own, drop the placeholder nodes `subscription.PlaceholderNode` names, dedupe by lowercased `server:port` first-wins in source order (`Entry.Addr` shares the lowercased key), relabel to `<source>-NNN`, and carry `NodeResult.IP` onto the entry. No annotation and no country decision happen here. The placeholder drop is here because this is the only gate on the worker's pool: the worker never calls `classify`, and `preprocess`'s IP filters judge geography, not reachability — under the shipped filter chain a loopback node passes them untouched. It cannot be skipped as cosmetic: a Nil-UUID credential authenticates nobody, a server naming the dialling machine reaches no remote, and the pool carries both. Measured by fetching all 98 configured source URLs with the worker's UA on 2026-08-14 (96 answered 2xx): 100 nodes on an unspecified or loopback address — 76 on `0.0.0.0`, 24 on the loopback `/8` — of which only 23 also carried a Nil UUID, and 4 sat on `127.0.0.1:8080` against a shipped `server.listen: :8080`, where `connect` passes `reachableTCP`'s bare `net.Dialer` and spends a full `URLTest` round probing the worker itself. The credential-plus-unspecified rule dropped 81 of those 100; judging the address as well drops all 100. The drop precedes the dedupe insert, so a placeholder cannot book a `server:port` a working node of a later source arrives on
- `SelectSurvivors(entries, results, rounds, maxFail, maxAvgMs) []Survivor` — keep `rounds-successes <= maxFail && mean <= maxAvgMs`, sort by mean ascending
- `LoadSnapshot(path string, logger) *Snapshot` / `SaveSnapshot(path string, s *Snapshot) error` (`snapshot.go`) — the `/stable.txt` list across restarts. An empty `path` disables both silently. The file is ONE JSON document (`payload` as UTF-8 text, not base64, so an operator can read it; `updated_at` RFC 3339; `stats` under snake_case keys) written through a same-directory temp file that is fsynced and then `os.Rename`d, so a reader observes either the previous document or this one and never a partial file; the temp is removed on every failure path. `LoadSnapshot` never fails a startup — a missing, unreadable, malformed or empty-payload file is a WARN that returns nil, which leaves the holder empty and `/stable.txt` on its `503`. An empty payload is rejected because `RunOnce` never publishes one, so such a file is not ours. There is NO TTL: that mirrors the in-memory rule (the last good list survives a failed cycle), and the age stays visible in `X-Stable-Stats updated=`. The marshal copies the payload once per PUBLISHED cycle — tens of minutes apart, right after a probe pass that dialled every node — which is the whole allocation argument for keeping one self-describing document instead of hand-streaming it
- `BuildPayload(ctx, ann preprocess.Annotator, survivors) []byte` — newline-joined URI list, and the ONE place a published name is built: for each survivor it parses `Entry.Raw`, hands the annotator `Egress.IP` when the trace answered and `Entry.IP` otherwise (the annotator never branches on which), prefixes `[SPD:<n>M] ` when the bandwidth filter measured one, and writes the returned country back into `Survivor.Country` — which is why `RunOnce` calls it BEFORE `observe`, since the kept-country and geo-unknown gauges read that field. A nil `ann` (annotation off) publishes `Entry.Raw` verbatim and leaves `Country` empty; a line that will not parse is published unannotated rather than dropped
- `entryLabel(px mihomo.Proxy) string` (`label.go`) — folds a mihomo proxy name back onto the `Entry.Label` it was built from. Every scheme but one names its single proxy exactly the label `Merge` wrote; `mierus://` is the exception, expanded by mihomo into one proxy per configured port named `<label>:<port>/<protocol>` (`common/convert/converter.go:662-696`). Without the fold every proxy-name-keyed map here misses on lookup by label, and a healthy mieru node is never selected, never checked, booked into the dead cache and counted `unreachable` by every through-node filter. The suffix is cut at the LAST `:` because neither a port (`2999`, `9998-9999`) nor a transport (`TCP`/`UDP`) can contain one while a source name can; the colonless/leading-colon guard matches no shape mihomo emits and exists so a future naming change degrades into an unfolded name rather than collapsing every mieru proxy onto `""`
- `NewMihomoProber(cfg config.CheckConfig, bandwidth config.BandwidthConfig, geo config.GeoBlockConfig, cf config.CloudflareConfig, geminiKey string, logger) (*MihomoProber, error)` — latency `Probe` (HEAD `URLTest`) plus through-node API checks: `GeminiCheck` + `GeminiEnabled()` (needs a key; alone among the checks it returns a second value, a `GeminiReport` accounting how much of its own verdict it obtained — a rejected credential is answered BEFORE the location precondition, so the count of responses that said nothing has to leave the function or the gate degrades invisibly), keyless `ClaudeCheck`, `ChatGPTCheck` and `TidalCheck`, and `BandwidthCheck`/`BandwidthMinMbps` (from the injected `bandwidth` config). The whole geoblock block travels as one param so a new API check adds a `GeoBlockConfig` field, not another parameter; `cf` is separate because the cdn-cgi/trace probe is no gate and lives under `geo.cloudflare`; `geminiKey` stays separate because only Gemini needs a credential. The trace URL is NOT a parameter: `cloudflareTraceURL` is a constant and the unexported `traceEndpoint` field is the test-only seam. API checks run through the shared `apiCheck` fan-out (mihomo `DialContext` + fixed-conn `http.Transport`, `GET` via `apiProbeOne`, which returns `(reachable, status, body)`; concurrency is clamped to >=1 because an unbuffered semaphore would deadlock the fan-out) and classify with one of two predicates: `markerBlocked` (body only, **fail-open** — Gemini: location marker; Claude: 403 `Request not allowed`; ChatGPT: 403 `unsupported_country` from `/compliance/cookie_requirements`) or `tidalBlocked` (status only, **fail-closed** — keeps a node only on 2xx; any non-2xx is the refusal, which is how Tidal's CloudFront 403 is caught, and unfollowed redirects make a 3xx interstitial a refusal too. The body is ignored on purpose: the gate answers only "did the request get through", so a 2xx from an ISP block page or a captive portal counts as passed). `GeminiCheck` also counts every response `geminiInconclusive` flags (401/403/404/429, plus a 400 carrying `API_KEY_INVALID`) and warns with the count: measured from a geo-blocked egress, `generativelanguage` resolves caller identity, then key validity, and only then the location precondition, so those answers predate the verdict entirely — treating them as "not blocked" is what turns the whole gate into a silent no-op the moment the key rotates.
- `NodeFilter` — through-node check applied after the IP-filters + latency probe, routing THROUGH each surviving node (worker-only, so it shapes `/stable.txt`, not `/`); selected from the unified `filters` list via `cfg.NodeFilterSpecs()` (types `gemini`/`claude`/`chatgpt`/`tidal`/`bandwidth`, all of them gates). The interface is one method: `apply(ctx, survivors, proxies map[string][]mihomo.Proxy) (kept, report)` — proxies GROUPED by entry label, because one label can hold several proxies (mihomo expands a `mierus://` link into one per configured port) and `filterSubset` puts ALL of them into the check subset, so a port dead on our egress cannot mask a live sibling; the checks fold the OUTCOMES back onto the label instead (`betterAPIOutcome` / `betterBandwidthOutcome`, best-of-ports, resolved under the map's own mutex at write time so the result does not depend on which worker finished last). A drop lasts exactly this cycle — the checker remembers nothing a filter decides; a verdict worth outliving the cycle goes to the geoblock store, which the filter writes itself and which `preprocess` then honours before the node is ever merged. `buildNodeFilters(names, prober, store, logger)` constructs them; one generic `apiFilter{filterName, enabled, check, store}` implements the interface for gemini (key-gated) and claude/chatgpt/tidal (keyless), each keeping API-reachable survivors. gemini alone is wrapped in a `geminiFilter`, which embeds that `apiFilter` and keeps its `GeminiReport` — the concept is gemini's alone (claude/chatgpt geo-block before authentication, tidal is fail-closed on a status code, so none can answer before its own verdict) and only a dedicated type can mark the DISABLED state, which `apiFilter.apply` returns from before it ever calls the check. `filterAndMeasureEgress` reads it back with a type assertion, the same optional-capability idiom as `spec.Prober.(traceChecker)`. A nil `enabled` func means always active; a disabled filter logs and keeps every survivor. gemini/claude/chatgpt record blocked hosts in the geoblock store; **tidal is built with a nil store on purpose** — its verdict is a bare status code, weaker than the AI checks' explicit refusal markers, and the store is host-keyed for its whole TTL, so one CDN hiccup would evict the node from every endpoint. With no store nothing outlives the cycle, so a rate-limited batch costs tidal's drop exactly one cycle.
- `TraceResult{IP netip.Addr, Country geofeed.CountryCode}` / `(*MihomoProber).TraceCheck(ctx, proxies) map[string]TraceResult` (`prober_trace.go`) — asks each node where its traffic actually leaves from, via Cloudflare's `/cdn-cgi/trace` (`key=value` lines; the body size is no property of the endpoint — it echoes the request User-Agent back in `uag=`, measured at 202 and 301 bytes for two of them — and nothing here sizes a buffer on it). `IP` is a fact — the address the endpoint saw the request arrive from; `Country` is Cloudflare's geo-IP lookup OF that address, still a database opinion but formed about the RIGHT address, which is the whole difference from the offline chain. Both are VALUE types rather than slices of the response body, because a result travels on to `Survivor.Egress` and its country becomes a Prometheus label inside the metrics snapshot. Runs its own fan-out rather than `apiCheck`'s, because that one folds every response into a blocked/reachable verdict and discards the body, and four production gates depend on its signature. `parseTrace` accepts a result only when BOTH fields are present and convert (`netip.ParseAddr`; two ASCII letters that are not Cloudflare's reserved `XX`) — a half-answer means the response did not come from the trace endpoint. A label covering several proxies (mieru's ports) folds by lowest proxy address, not by whichever goroutine finished first
- The egress stage is NOT a `NodeFilter`: `filterAndMeasureEgress` (`checker.go`) runs `TraceCheck` after the whole filter chain, over the same parse-once proxy set, and records each answer in `Survivor.Egress` without dropping anything. The offline annotate chain places the address the RESOLVER returned, and 41% of the pool's named hosts sit in Cloudflare's shared anycast ranges (104.21/16, 172.67/16) which terminate in many countries at once — so the tag described Cloudflare's registration while the traffic left from the origin (a node tagged CA exiting in Germany). Measured on 102 live nodes: 47 tags corrected, 16 unanswered, and among named hosts the egress address differed from the resolved one in 12 of 18 cases. The answer is only ever RENDERED by the `cloudflare` annotate provider, so `annotate` without it disables the probe outright (`CheckerSpec.Trace`), and a prober that cannot trace logs a warning and skips the stage. It runs last on purpose: a node a later gate would drop must not spend a request on a tag nobody sees
- The `bandwidth` `NodeFilter` (`bandwidthFilter`) downloads the bandwidth filter's `test_url` through each survivor (`BandwidthCheck` → `bandwidthProbeOne` → `measure`, `Accept-Encoding: identity` + body-transfer timing; `computeMbps` guards divide-by-zero), drops nodes below `min_mbps` and unreachable ones, records `Survivor.Mbps` and nothing else — the `[SPD:<n>M]` prefix that measurement earns is rendered once, by `BuildPayload`. `measure` reports a sample ONLY for a 2xx response read to completion, or one our own deadline cut short (a legitimate sample of a slow node): a non-2xx, an unfollowed redirect, or a body the peer truncated is a few fast kilobytes that `computeMbps` would inflate into a large fabricated rate, so it is reported not-reachable instead. It persists nothing: the concurrent downloads share one host uplink, so a dip on our side puts the whole batch under the floor, and next cycle re-measures.
- `NewChecker(spec CheckerSpec, filterer func() Filterer, store Blocklist, dead DeadCache, holder *Holder, snapshotPath string, logger, reporter Reporter)` / `(*Checker).Reconfigure(spec)` / `(*Checker).Run(ctx)` — immediate first cycle, then ticker (`Run` resets the ticker when a reload changed `Interval`); `Reconfigure` atomically swaps the spec and the cycle in flight keeps the one it started with. The `store` is held ONLY to prune it; the writes still happen inside each `apiFilter`. `RunOnce(ctx) error` is one cycle and loads the spec ONCE up front, threading it (and the ONE `Filterer` the whole cycle uses) into `fetchSources`/`filterAndMeasureEgress` so a mid-cycle reload cannot half-rewrite it: fetch sources concurrently (results kept in config order so first-source-wins is deterministic), drop dead-cached nodes before probing, probe the rest, record no-success nodes as dead (short TTL), `SelectSurvivors`, apply the configured `NodeFilter`s, measure the survivors' egress, then `pruneCaches` (dead cache + geoblock store), and finally `BuildPayload` — before `observe`, because it is what fills `Survivor.Country`. A cancelled/failed probe aborts the cycle: the previous snapshot is kept and nothing is recorded dead (a shutdown mid-probe can't poison the dead cache; a reload no longer cancels a cycle at all). `Probe` shares ONE semaphore across rounds — built by the same `fanoutSem` as the API and bandwidth fan-outs, so `check.concurrency` caps total in-flight URL tests and a hand-built `Concurrency: 0` degrades to serial instead of deadlocking. `fetchSources` builds each `preprocess.FilterRequest` per source: when `src.Body != ""` it passes `Body: []byte(src.Body)` with an empty `SubscriptionURL` (inline path, no fetch), otherwise the usual `SubscriptionURL: fetch.SubscriptionURL(src.URL)`; the local `Filterer` interface is `FilterNodes(...)` plus `Annotator()`. Right after the `holder.Store`, the same `*Snapshot` goes to `SaveSnapshot(c.snapshotPath, snap)`; a write error is a WARN and nothing else, because a snapshot that cannot be written costs the NEXT restart its head start and nothing in this cycle. `snapshotPath` sits with the fixed fields rather than in `CheckerSpec` — a reload must not change it (`config.StoresChanged`).
- `NewController(ctx, holder, filterer func() Filterer, store Blocklist, dead DeadCache, snapshotPath string, logger, reporter Reporter)` / `(*Controller).Apply(cfg) error` / `(*Controller).Stop()` — `Apply` builds the denied `CountrySet` via `cfg.DeniedCountries()`, folds each through-node spec's per-entry overrides back into a `GeoBlockConfig` copy, resolves the Gemini key, reads `cfg.AnnotateUsesProvider(config.ProviderCloudflare)` into `CheckerSpec.Trace`, and builds the prober + `NodeFilterSpecs`-selected filters BEFORE touching the worker (a failed construction leaves the previous spec in force), then hands the resulting `CheckerSpec` to the running `Checker` via `Reconfigure` — or starts one when none is running and `subscriptions.sources` is non-empty. A reload NEVER restarts a live worker: the cycle in flight runs to publication instead of being cancelled and losing its whole probe pass. A reload whose merged source list is **empty** is refused rather than obeyed — with a worker running it logs a warning and keeps the previous spec live (every source comes from an overlay, so an empty list is nearly always a missing `sources.yaml`/`private.yaml`, and stopping would cancel the cycle in flight and freeze `/stable.txt` with nothing behind it); with none running it stays a no-op. `Stop` is idempotent, clears the checker, and is now reached only on shutdown. The `reporter` (nil-safe) is threaded into every `Checker` it builds.

**Uses:** `config`, `filter`, `fetch`, `preprocess`, `subscription`, `ioutil`, `mihomo` (adapter, common/convert, common/utils, constant)
**Tags:** `stable`, `probe`, `url-test`, `gemini`, `claude`, `chatgpt`, `tidal`, `cloudflare`, `bandwidth`, `speed`, `geoblock`, `delay`, `worker`, `mihomo`, `atomic-swap`

## `internal/metrics`

`./internal/metrics/metrics.go`

Renders the stable worker's per-cycle stats as Prometheus text exposition (hand-rolled — no `client_golang`, avoiding the `google.golang.org/protobuf => metacubex/protobuf-go` replace). Served on an internal listener (`server.metrics_listen`, default `:9090`) that docker-compose publishes loopback-only, once per instance: `127.0.0.1:9091:9090` for `sub-preprocessor` and `127.0.0.1:9092:9090` for `sub-preprocessor-vassago`. `deploy/monitoring.nix` scrapes each under its OWN job name — one job per instance, not two targets in one — because the dashboard's Instance picker is `label_values(stable_cycles_total, job)` and two targets sharing a job are unselectable. Every panel expression is therefore `{job="$job"}`-scoped.

**Key exports:**
- `Metrics` — holds the last `stable.CycleReport` + lifetime counters (RWMutex); `New()` constructs it
- `(*Metrics).Observe(stable.CycleReport)` / `ObserveError()` — satisfies `stable.Reporter`; both count toward `stable_cycles_total`, ObserveError also bumps `stable_cycle_failures_total`
- `(*Metrics).Handler() http.Handler` — renders `/metrics` into a buffer under a read lock, so a slow scrape never blocks `Observe`
- `escapeLabelValue(s)` — one invalid byte fails the whole label value (`prometheus/common model.LabelValue.IsValid` is `utf8.ValidString`) and takes the ENTIRE scrape with it, so an invalid-UTF-8 value is replaced with `invalid_utf8` rather than escaped; `labelValueEscaper` then handles exactly the three characters the text format reserves — `\`, `"`, `\n` — and deliberately NOT `\r`, which the parser copies through while a `\r` escape is one it rejects. The label that can actually arrive dirty is `country`: it is never re-parsed out of a published `[GEO:xx]` name — `BuildPayload` writes the annotator's RETURN value into `Survivor.Country` (`stable/select.go:90`), so with `annotate: []` the annotator is nil, `Country` stays `""` and `keptCountries` skips it (`stable/checker.go:296`) — but when annotation is on it is still two bytes that came off the wire, and only two of the four providers vet them: `geofeed.parseLine` accepts ANY two bytes as a country code (`geofeed/geofeed.go:118-131` checks length and folds case, nothing more) and the Cymru TXT parse does the same (`asn/resolver.go:191-196`), while dbip (`geofeed/dbip.go:104-116`) and cloudflare's trace (`stable/prober_trace.go:validCountry`) demand ASCII letters. The other label values cannot reach here dirty — `filter` and `reason` are in-tree constants, `source` is validated `^[a-z0-9-]+$` at config load (`config/config.go:113`, `:1285`) — so this is one reachable path plus defence in depth for the rest

**Metrics:** `stable_gemini_gate_{enabled,checks,unverified_checks}` (the gemini gate's self-account — `unverified_checks` counts responses that predate the location verdict and whose nodes were KEPT, so it is deliberately NOT a `stable_filter_dropped_nodes` reason; all three are absent when no gemini filter runs and `enabled` is 0 when it is configured without a usable key), `stable_kept_nodes`, `stable_merged_nodes`, `stable_probed_nodes`, `stable_probe_outcome_nodes{stage}` (`stage` = `condemned`/`connect`/`fetch`/`passed`, summing to `stable_probed_nodes`; `stage="unknown"` renders only when the prober left probed nodes unclassified, and the whole family is absent when a report carries no fold rather than four misleading zeros), `stable_dead_skipped_nodes`, `stable_sources_ok`/`_total`, `stable_cycle_duration_seconds`, `stable_cycle_phase_duration_seconds{phase}` (`phase` = `fetch`/`merge`/`dead_filter`/`probe`/`egress`/`publish`, one metric rather than six names; the phases sum to slightly less than `stable_cycle_duration_seconds` because the steps between them belong to no phase), `stable_last_success_timestamp_seconds`, `stable_cycles_total`/`_failures_total`, `stable_filter_{in,kept,dropped}_nodes{filter,reason}`, `stable_source_{nodes_total,kept_nodes,dropped_nodes}{source,reason}`, `stable_geo_unknown_nodes`, `stable_kept_country_nodes{country}`, `stable_trace_{answered,unanswered,moved}_nodes`, `stable_kept_speed_mbps` (histogram) alongside `stable_kept_speed_{min,max}_mbps`, and `stable_kept_latency_ms` (histogram) alongside `stable_kept_latency_{min,max}_ms`. The two kept-node trios are deliberately the same shape and share one `writeHistogram`, which takes its bounds as a parameter — `speedBuckets` (Mbps) and `latencyBuckets` (ms) — because the units are unrelated and one ladder cannot serve both. **`latencyBuckets` MUST carry a bound equal to every `check.max_avg_ms` that any shipped config sets**, and a threshold moved anywhere else adds its bucket in the SAME commit: `max_avg_ms` is what `SelectSurvivors` admits on, so a threshold falling between two bounds hides the one edge this histogram was added to make visible. The two instances publish this metric name under different Prometheus jobs and are free to disagree on the threshold, so the ladder carries each of them rather than one. `stable_dead_skipped_nodes` counts every merged node the cycle did not probe — all of them dead-cached, the only pre-probe skip left — so the funnel closes: `merged = dead_skipped + probed`. `stable_source_dropped_nodes` reasons: `dns`, `geo`, `cidr`, `asn`, `geoblock`, `ipv6`, `unsupported` — `unsupported` counts unparseable INPUT LINES and is therefore not part of `stable_source_nodes_total`. Adding `cidr` needed no new metric NAME and no panel or query change: the reason is a label value, and the "IP-stage drops by reason" panel is `sum by (reason) (stable_source_dropped_nodes{job="$job"})`, which enumerates nothing. Its DESCRIPTION does enumerate them in prose, so that one string did change on this branch — a reason added to `Stats` has no query to update and one paragraph that must be. The trace trio accounts the cloudflare stage over the PUBLISHED set: `applyTrace` drops nothing, so `answered + unanswered = kept` whenever the stage ran, and all three read 0 when no `cloudflare` provider is configured (`CheckerSpec.Trace` false → the zero `TraceReport`). `moved` counts answered nodes whose published country differs from the one the offline chain gives for their RESOLVED address — the correction rate that pays for one extra request per survivor, trustworthy only to the extent `answered` dominates. `stable_geo_unknown_nodes` counts published `[GEO:??]` nodes and `stable_kept_country_nodes` the rest by resolved country; neither counts a survivor left uncountried because annotation is off or its line would not parse, so the two sum back to `stable_kept_nodes` only with annotation on and every line parsed.

**Uses:** `stable`
**Tags:** `metrics`, `prometheus`, `grafana`, `exposition`, `observability`

## `internal/reload`

`./internal/reload/reloader.go`, `watcher.go`, `options.go`

Config hot-reload. Watches the config file **and its `private.yaml` / `sources.yaml` overlay siblings** for changes (via fsnotify on the parent directory), debounces bursts, and atomically swaps the active `Processor` + groups into the server `Holder`. On any error the previous settings are kept unchanged. The overlays matter because the crawler writes `private.yaml` and `sources.yaml` carries curated sources, and a change to either must reach the stable worker, which is reconfigured in place rather than restarted.

**Key types:**
- `Reloader` — holds `path`, `*server.Holder`, `zerolog.Logger`, and the last-applied `config.Config` + `*preprocess.Processor` for diffing
- `Applier` — interface `Apply(config.Config) error`; satisfied by `*stable.Controller` (enables fake controllers in tests)
- `Watcher` — wraps `*fsnotify.Watcher`; watches the config file's parent directory to survive atomic-rename writes; fires `onChange` for events on `config.yaml` or its `private.yaml` / `sources.yaml` siblings; debounces events with a 200 ms window. `matches` compares each event against exactly those three paths, so every OTHER resident of `config/` is inert for reload purposes: `channels.yaml` (crawler seed list, re-read by the crawler itself each cycle), `private-example.yaml`, `.geoblock.db*`, `.crawler-state.json`, and the per-cycle temp-create + rename behind `subscriptions.snapshot_path` (shipped as `/config/.stable-snapshot.json`). Adding a state file to that directory therefore costs no reloads

**Key functions:**
- `NewReloader(path string, holder *server.Holder, logger zerolog.Logger, cfg config.Config, proc *preprocess.Processor, ctl Applier, blocklist preprocess.Blocklist) *Reloader` — seed with startup state so the first reload can diff against it; injects the shared geo-block store into every rebuilt `Processor`
- `(*Reloader).carryLoadedState(opts *preprocess.Options, newCfg config.Config)` — the six carry-over gates in one place: geofeed / dbip / registry `GeoState`, the cidr `CIDRState`, and the live DNS and Cymru resolvers, each guarded by its own `config.*Changed` helper. Every guard diffs `currentProcCfg`, the config that BUILT the current processor, not `currentCfg`: the two diverge after a failed `ctl.Apply`, and carrying data across the wrong source set would serve stale answers. A zero state — the provider or the `cidr` filter absent from the current processor — simply leaves the preload unset. The DNS and Cymru caches are the odd pair: their value IS the cache rather than a download, and dropping them would re-resolve every host on the next cycle, so their configured TTLs would never be reached under the crawler's hourly `private.yaml` rewrite
- `(*Reloader).Reload(ctx context.Context)` — load config → skip only if `Equal` against BOTH `currentCfg` and `currentProcCfg` (they diverge after a failed `Apply`, and keying the fast path on `currentCfg` alone made reverting the file a silent no-op that left the holder serving the rejected config) → build `OptionsFromConfig` (+ inject `Blocklist`) → `carryLoadedState` → `NewProcessor` → `SetLevel` → warn if `ListenChanged` or `StoresChanged` (restart required) → `holder.Store` new snapshot → `ctl.Apply(newCfg)` when `SubscriptionsChanged || GroupsChanged || FiltersChanged || ProberChanged || AnnotateChanged`. On a failed `Apply`, `currentCfg` is NOT committed, so re-saving the file retries instead of hitting the `Equal` fast path (the worker keeps running on its previous spec — Apply builds the prober/filters before swapping it in, and never stops the worker). A `NewProcessor` that fails keeps the previous processor whole, which is what makes the cidr allow-list's fail-closed build safe to hot-reload into: an edit pointing `filters[].urls` at a 404 leaves the running instance on the list it already has
- `NewWatcher(configPath string, onChange func(context.Context), logger zerolog.Logger) (*Watcher, error)` — register fsnotify watch on parent directory; return error if watcher or directory watch fails
- `(*Watcher).Run(ctx context.Context) error` — event loop: debounce matching events, call `onChange` once per burst; close fsnotify watcher on ctx cancellation and return nil (callers use the return as a join point)
- `OptionsFromConfig(cfg config.Config) preprocess.Options` — single source of truth for mapping `config.Config` to `preprocess.Options` (incl. `geo.dbip` → `DBIP`, `geo.registry` → `Registry`); the cidr filter needs no field of its own, since its spec rides `IPFilterSpecs()`. Leaves every `Preloaded*` field unset (callers decide whether to carry over geofeed/dbip/registry state, the cidr allow-list and the DNS/ASN resolvers)

**Uses:** `config`, `geofeed`, `log`, `preprocess`, `server`, `stable`, `fsnotify`
**Tags:** `reload`, `fsnotify`, `hot-reload`, `watch`, `atomic-swap`, `debounce`

## `internal/classify`

`./internal/classify/classify.go`

Decides whether a URL serves a usable Mihomo-compatible subscription, reusing the project's HTTP client (the caller supplies it — the crawler an unrestricted client, the `classify` CLI a guarded one) and the same normalizer/parser the preprocessor uses. Used by the `crawl` subcommand and the `classify` CLI subcommand.

**Key types:**
- `Result{Nodes int, Expired bool}` — `Nodes` counts USABLE nodes only, so `(Result).Live()` reports `Nodes > 0 && !Expired`; `(Result).Reason()` names WHY as an enumerable `Reason` (`live` / `expired` / `nodeless-2xx`), derived from the same two fields rather than stored, so no `Result` can carry a verdict contradicting its counts. `Expired` outranks a zero node count: an origin-advertised expiry is a death verdict, a nodeless 2xx is not
- `StatusError{Code int, Status string}` — a non-2xx answer; `(*StatusError).Gone()` reports the **definitive** codes only (404/410/451). Every other status (403 WAF/geo-block, 408/425/429 back-pressure, all 5xx) is transient, so a caller that deletes on a dead verdict must not delete on those

**Key functions:**
- `Body(body []byte, subUserinfo string, now int64) Result` — pure classifier: base64-normalizes the body, counts only **proxy-scheme** nodes (`vless`/`vmess`/`ss`/`ssr`/`trojan`/`tuic`/`hysteria`/`hysteria2`/`hy2`/`anytls`/`mierus`) that are not placeholders, and marks expired from a `subscription-userinfo: expire=` header. mihomo also converts `http`/`https`/`socks`/`socks5`/`socks5h`, and they stay OUT of the whitelist on purpose: `parseNode` rejects only the PORTLESS form, so a portful `https://example.com:8443/docs` in a docs page or a panel's client-setup snippet IS a valid `Node` to it, and counting those would make the pages this gate exists to reject read as live subscriptions
- `subscription.PlaceholderNode` (in `internal/subscription`, NOT here) — the fourth producer of `nodeless-2xx`, beside the captive portal, the CDN interstitial and the panel login page. A dead panel may answer 200 with ONE parseable node that can never carry traffic: a Nil-UUID credential (RFC 9562 §5.9, all 32 digits, so a short all-zero password still counts) that authenticates nobody, or a server naming the machine that would dial it (the unspecified address, the loopback `/8`, `::1`), which reaches no remote. Measured on the motivating panel, the header gate cannot see that death — it advertised an `expire=` still in the FUTURE while its body said otherwise. The verdict is deliberately nodeless and NOT a new death verdict, so `Prune`'s refusal to delete on a merely-nodeless body still holds. It sits in `internal/subscription` because `stable.Merge` applies the same rule to the worker's probe pool and the worker never calls `classify`: two copies could disagree, and a URL classifying dead while its nodes went on being probed is exactly the split that motivated the move
- `URL(ctx, client *http.Client, rawURL fetch.SubscriptionURL) (Result, error)` — scheme-validate + fetch + `Body`; a non-2xx answer returns `*StatusError` (check `Gone()` before acting on it); the IP/SSRF policy comes from the passed client

**Uses:** `fetch`, `subscription`
**Tags:** `classify`, `subscription`, `ssrf`, `crawler`

## `internal/crawl`

`./internal/crawl/crawl.go`, `discover.go`, `reject.go`, `state.go`, `channels.go`, `http.go`

Format-agnostic, recursive subscription crawler. Scrapes public Telegram channel web previews (`t.me/s/<channel>` + `?before=` pagination), treats **every** https link as a candidate, keeps the ones that `classify` as a live subscription, and writes them to the `private.yaml` overlay as `tg-<channel-slug>-<sha6>` sources — the discovering channel (first-wins in BFS order, so seeds beat discovered channels) plus a 6-hex URL hash; `channelSlug` folds the Telegram slug into the config name alphabet (`^[a-z0-9-]+$`, `_`→`-`, 24-byte cap). An already-attributed name is kept verbatim across cycles (renames would churn private.yaml and relabel published nodes); a legacy pure-hash `tg-<sha10>` name upgrades the first time its URL is rediscovered in a channel; a name collision or unknown origin falls back to the `tg-<sha10>` form (`sourceName`). Matches the artifact (a URL that returns a subscription), not any channel-specific wrapper pattern. Runs as the `crawl` subcommand in the same image as the service. One **unrestricted** `http.Client` (no IP guard — it reaches `t.me` through the host's local fake-ip tunnel and follows links scraped from channel content) is held on the `Crawler` and reused for pages + classify batches. Cycle hygiene: a cancelled or budget-exhausted ctx aborts before any state/private.yaml write, and `Run`/`RunDaily` bound each cycle to `cycleBudget` (¾ of the schedule interval, capped at 2h) so a growing crawl cannot outrun its own tick.

**Key types:**
- `Options{Channels []string, ChannelsPath string, PrivatePath string, Pages int, Prune bool, MaxDepth int, MaxChannels int, StatePath string, StateTTL time.Duration, InlineEnabled bool, InlineMax int}`
- `Crawler` — `New(opts, logger)`; `RunOnce(ctx)` the bare cycle (what `CRAWL_RUN_ONCE=1` calls directly), `Run(ctx, interval)` loop, `RunDaily(ctx, hour, minute)` at a daily wall-clock time, `Serve(ctx, addr)` the optional trigger listener (`CRAWL_HTTP`: `POST /crawl` → 202, 409 while a cycle is in flight; `GET /healthz`). Every *scheduled or triggered* cycle takes the same `running` mutex with `TryLock` — `Run`/`RunDaily` through `runGuarded`, the handler inline so its 202/409 is accurate — so a tick or trigger colliding with a live cycle is skipped rather than queued; only the `runGuarded` paths also bound the cycle by `cycleBudget`

**Behavior:** `scan` (in `discover.go`) does a **relevance-gated BFS** over the channel repost graph — seeds are crawled unconditionally, a discovered channel (`extractChannels`: forwarded-from/@mention `t.me/<slug>` links, excluding self/reserved/bot `?start=`) is expanded only if it itself yielded a live subscription; the subscription yield is the thematic signal (a VPN channel forwards VPN channels; a news channel yields nothing and its branch stops). Depth is bounded by `MaxDepth`; `MaxChannels` caps discovered (non-seed) visits per cycle (`0` = the built-in `defaultMaxDiscovered`, 200 — never unlimited, since every discovery can promote itself to a seed). Only operator-configured seeds get the full `Pages` budget; remembered seeds and discovered channels get `discoveredPages` (3), which is what stops each cycle from costing more than the last. A per-cycle `visited` set means every channel is fetched at most once and a repost loop (A→B→A) can never re-enter an explored channel. Page fetches are sequential (rate-limit friendly). Validates candidate URLs via `fetch.ValidatePublicHTTPSURL` — the same rule `config.Load` applies, so a harvested literal-private-IP URL can never make the whole config unloadable — and skips Telegram/CDN noise hosts before fetching; classifies concurrently. **Pruning is evidence-based:** a managed source is dropped only on a definitive verdict — an expiry the origin itself advertised (`Result.Expired`), or a `classify.StatusError` whose `Gone()` is true (404/410/451). A transport failure, a transient status, **or a 2xx carrying no proxy-scheme node at all** retains it: since `Body` counts only real node schemes, a captive portal, a Cloudflare interstitial and a panel login page all come back nodeless, and that is "alive but told us nothing", not proof of death. Such a source is retained for *that cycle*, not forever: `trackLiveness` advances a per-URL not-live streak and `retainManaged` retires the source once it reaches both `staleRetireCycles` (6) consecutive not-live cycles and `staleRetireAfter` (24h) of wall clock — see **Persistence**. A cycle that discovered nothing *and* revived nothing prunes nothing (`recheckResult.dark` — that shape is a crawler-side egress fault, not mass death), and `allowShrink` refuses any write dropping both >10 managed sources and >30% of them until a later cycle re-proposes substantially the same deletion (see Persistence). Hand-added private sources are preserved; `writePrivate` re-validates the whole file against the consumer's rules (name alphabet, uniqueness, public https URL) and refuses to author a config the service cannot load; only rewrites `private.yaml` (atomic temp+rename) when the managed set changes, so unchanged cycles trigger no reload.

**Persistence (`state.go`):** channels that yield a live subscription are recorded in a JSON state file (`StatePath`, default `/config/.crawler-state.json`) and become depth-0 seeds on future cycles — always crawled and always expanded — so a proven-productive channel keeps growing the graph even on days its recent pages carry no live sub. Entries with no live sub for `StateTTL` (default 30d) are pruned, and the memory is then capped at `maxProductive` (200) most-recently-productive channels, bounding the seed set that drives every cycle's cost. The same file carries per-managed-source liveness under `managed`, keyed by URL: `last_live_at`, `not_live_since` and `not_live_cycles`. `ageManaged` clears that streak on any cycle where the source serves nodes (rediscovered in a channel or revived by a recheck) and advances it on any cycle where it does not, and a source is retired only once the streak reaches BOTH `staleRetireCycles` (6) and `staleRetireAfter` (24h) — wall clock alone would let a crawler resuming after days of downtime delete on one bad answer, and a cycle count alone is burned through in minutes by back-to-back `CRAWL_HTTP` triggers. A missing record means *no history yet*, never stale since the zero time: the streak is anchored at the observation that opens it, which is what grandfathers a corpus predating this bookkeeping instead of condemning all of it on the first cycle. `last_live_at` is what separates *no history* from *was live, then stopped* in the condemnation log. A dark cycle advances no streak (its not-live answers are a crawler-side fault, not evidence), the map is bounded by the corpus rather than by a TTL (a record whose URL `private.yaml` no longer holds is dropped), and a retirement is an ordinary deletion, so the bulk-prune floor still gates it. The file also carries the refused bulk prune as `bulk_prune_at` + `bulk_prune_urls` — when `allowShrink` refused it, and the sorted set of managed URLs it condemned. A later cycle carries it out only if it re-proposes at least `bulkPruneOverlap` (80%) of that set (symmetric, so the new proposal may be neither much smaller nor much larger), at least `bulkPruneConfirmAfter` (6h) but no more than `bulkPruneRecordTTL` (24h) after the refusal; honouring it consumes the record. Any other proposal — a different set, or one arriving past the TTL — replaces the record and starts its own wait, and any cycle whose merge proposes no bulk deletion at all withdraws the record. The URL set is what makes the record consent to one specific deletion instead of to the next one that happens along. Empty `StatePath` disables persistence — and therefore refuses every bulk prune, the safe direction. A read or unmarshal failure is logged at ERROR and marks the stand-in state `loadFailed`, which makes `saveState` a no-op for the rest of the cycle: an EACCES or a truncated file costs one degraded cycle instead of silently overwriting up to 30 days of channel memory with an empty file. A genuinely corrupt file must be deleted by hand.

**Inline-node harvest (`InlineEnabled`, default on):** alongside https subscription links, each channel's **first (newest) scraped page only** is scanned by `extractInlineNodes` for **raw proxy URIs pasted directly in messages** (`vless|vmess|ss|ssr|trojan|tuic|hysteria2|hysteria|hy2|anytls|mierus://…`, HTML-unescaped, trailing punctuation trimmed; `http`/`https`/`socks*` are absent for the same reason as in `classify` — `parseNode` rejects only the portless form, so harvesting them would turn every documentation link a channel posts into a proxy). Only the inline scan is head-only — subscription candidates still come from every page — because `scrapeChannel` walks backward via `?before=`, so pages 2..N are older by construction, and a pasted node is a frozen `server:port` whose survival tracks the age of the message that carried it: 7.4% of nodes from messages ≤1d old pass the shipped probe gate (n=162) against 2.8% at 1-3d (n=178). Per cycle the URIs are accumulated across those first pages, parsed with `subscription.Parse`, deduped by lowercased `server:port` (first-wins, mirroring `stable.Merge`), and capped to `InlineMax` (default 500, first N kept). When ≥1 node survives, `buildInlineSource` packs the kept node URIs into a single base64 `Body` under a managed `tg-inline` source appended to `private.yaml` (empty-URL source → the stable checker filters `Body` directly, no fetch); a cycle with 0 inline nodes omits the source. `mergeManaged` skips existing `Body` sources so `tg-inline` is regenerated fresh each cycle, and `sameSources` includes `Body`, so a changed inline set triggers a private.yaml rewrite + reload. Env: `CRAWL_INLINE` (default `true`) toggles the harvest; `CRAWL_INLINE_MAX` (default `500`) sets the cap.

**Seed config (`channels.go`):** `config/channels.yaml` (`ChannelsPath`) carries two lists: `channels: [slug|@handle|slug/topic|t.me-url]` (depth-0 seeds; a trailing `/<topic>` names a Telegram forum topic — see **Forum topics** below) and `blocked: [url]` (subscription URLs the crawler must never manage). `loadChannels` returns the parsed `channelsFile` and is best-effort (missing/malformed → empty, never fatal), re-read every cycle, so both lists hot-reload without a restart. Effective seeds = `channels.yaml` ∪ `CRAWL_CHANNELS` env ∪ remembered productive channels. `blocked` is applied in `mergeManaged`, the single funnel every candidate URL passes through, so a retired source cannot re-enter from the re-loaded file, from rediscovery in a channel, or from `recheckManaged` reviving it — hand-deleting it from `private.yaml` alone does not stick.

**Pagination health:** `scrapeChannel` returns `cursorLost` when a fetched page carried no `?before=` cursor while the page budget still had room — the signature of the one undocumented `data-post` attribute (`cursorRe`) being renamed. `scan` aggregates the per-channel outcomes into `cursorStats` and `reportCursors` warns once per cycle when every cursor-relevant channel (at least `cursorAlarmMin`, 5) lost its cursor. Per channel the signal is noise (short channels legitimately have one page); fleet-wide it is the selector breaking and silently cutting `CRAWL_PAGES` to 1. A seed read through a forum topic never votes in that ratio: a group's `t.me/s/` probe answers with no message and no cursor, and that empty listing is dropped rather than counted (counting it would report a 100% loss for every forum seed, every cycle), while the topic listing itself carries no cursor at all and is fetched once. A channel seed votes normally whether or not its entry carried a topic id, because it is read through the listing either way.

**Forum topics:** a group/forum chat has **no `t.me/s/` web preview** — measured 2026-08-14, `t.me/s/<chat>` answers 200 with zero `tgme_widget_message_wrap`, which is neither an error the crawler could log nor a page it could harvest. `parseSeed` therefore keeps a seed's numeric second segment as `chanRef{slug, topic}` (a permalink's trailing message id, and any non-numeric segment, is dropped; a reserved path yields the empty ref), and `scrapeChannel` still walks the `t.me/s/` listing **first** for every seed, falling back to `scrapeTopic` only when a topic-carrying ref's listing came back with no `tgme_widget_message_wrap` at all. That inversion is forced by measurement: a channel post's discussion embed answers 200 with **one** message wrap (`t.me/<chan>/<msgid>` + `topicQuery`, 3527 B), so reading the embed first *succeeds* for a plain permalink seed and silently replaces a 20-message listing page with a single message — while `t.me/s/<channel>` returns 20 wraps and 20 cursors and `t.me/s/<group>` returns none, which is the discriminator the feature needed all along. `scrapeTopic` fetches `t.me/<chat>/<topic>` + `topicQuery` (`?embed=1&discussion=1&comments_limit=50`) — the one shape measured to return the topic's messages **and their links**; the `<chat>/<topic>/<msg>` permalink form returns none. The listing saturates at 3 message wraps for `comments_limit` 50/100/200 and that ceiling is accepted, because a link rotating every 24h is only useful from the newest messages and walking message ids instead measured ~1182 requests per pass. The body is the same `tgme_widget_message` markup, so `harvestPages` extracts from it unchanged (`extractURLs` + `extractInlineNodes`). A live URL is attributed to the **bare slug** — a managed source name is permanent, a topic id is not — while `state` remembers the productive ref **with** its topic, since re-seeding the next cycle with the bare chat would go back to the message-less `t.me/s/` shape. A topic body with no message wrap means the seed yields nothing at all (its `/s/` listing was already empty), and warns distinctly from a failed fetch, so a topic that went empty is never read as one that was never reachable. The cost of the inversion is one wasted fetch per genuine forum seed per cycle — the empty `/s/` probe — and nothing at all for a channel seed, permalink or not. A chat is **one crawl target per cycle, keyed by its slug**: `buildSeeds` merges every entry naming the same chat (configured wins, and the first topic named wins over none, since a needless topic falls back while a dropped one leaves a group unreadable) and `scan`'s `visited` set is slug-keyed, so a chat seeded with a topic and reposted bare is not scraped twice — the second, bare scrape would fetch the group's message-less `t.me/s/` page and read it as a lost cursor. Discoveries stay bare for the same reason: the three-segment `t.me/<chat>/<topic>/<msg>` form does identify its topic, but a reposted link names one topic of a chat arbitrarily, and which topic of a group is worth reading is a judgement only the operator's seed carries.

**Per-candidate reject logging (`reject.go`):** every discovered URL that fails a `candidate` gate, or that `classifyAll` does not classify live, emits one INFO line (up to `maxRejectLines` per cycle) naming the channel, the `tg-<slug>-<sha6>` identifier `sourceName` would give it *in that channel*, the host, and a `rejectReason` — `noise-host` / `invalid-url` (`candidate`'s two reject reasons — three gates, since its `url.Parse` and its `ValidatePublicParsedHTTPSURL` gate both report `invalid-url`) or `bad-status` (+ `status`) / `fetch-failed` / `nodeless-2xx` / `expired` (the `classifyAll` verdicts). INFO, not DEBUG: the crawler is a separate process that never loads `config.yaml`, `log.InitDefault` pins the global zerolog level to info before the subcommand switch, and `Options` has no level knob, so a DEBUG line would emit zero times in production. **Neither the path nor the query is logged.** The query carries `?payload=<base64>` on the observed corpus, and the path is credential-bearing too — Marzban serves `{prefix}/{XRAY_SUBSCRIPTION_PATH}/<USER_TOKEN>` and 3x-ui `/<subPath>/<subId>`, neither with a query at all — so keeping even a prefix of the path would publish the credential for those panels; the `sha6` is the identity instead. `safeError` swaps the candidate's URL out of any error text and drops the text entirely when a URL still survives in it (a refused redirect names a SECOND URL that no substitution can reach), logging `redacted: error names the candidate url` instead. **A second, independent rule sits behind that one** (`namesSecret` -> `redacted: error names the candidate url path or query`): an error naming only the candidate's PATH or QUERY carries no `://` for the survivor check to see and no whole URL for the substitution to match, and for Marzban and 3x-ui the path IS the credential. It substring-matches and is deliberately over-eager, so **an operator meeting that second string should read it as a false positive first**: a candidate whose path is `/o` matches the `i/o` of `dial tcp: i/o timeout`, and `net/http: TLS handshake timeout` carries a slash of its own, so the two commonest crawler failures can lose their diagnosis to a short path. Only once the candidate's own path and query are checked against the message the code would have produced, and cannot collide with it, does the string mean the other thing — that an error on the reject path grew a shape none produces today, and the code it names needs a look. `rejects` dedupes by URL — one link recurs across posts, pages and channels — caps the lines at `maxRejectLines` (200, = `defaultMaxDiscovered`), and closes the cycle with one summary line carrying the total and a count per reason, followed by a second line reporting how many per-candidate lines the cap withheld. The dedupe set is bounded too, by `maxRejectTracked` (20000, = `maxInlineAccum`: the twin accumulator the same per-page scan feeds — since the inline harvest went head-only that one sees a channel's NEWEST page while this set spans every page scraped, so the shared bound is a deliberate mirror rather than a shared population — and unlike `live` this one has no network brake, since a URL failing a `candidate` gate costs only local string work). Past that bound a new URL is neither tracked nor counted by reason; the overflow is reported as `untracked=<n>` on the summary line. **`untracked` is deliberately outside `rejected` and outside every per-reason column** — past the bound a repeat cannot be told from a new candidate, so folding it in would inflate both — which is why the per-reason counts still sum exactly to `rejected` (`TestRejectSummaryCountsSumToTotal`), and why an operator reading `untracked=57` should read it as "57 rejections this cycle went unaccounted, and the numbers beside them are the accounted ones". The column set cannot go stale: `rejectField` is a `map[rejectReason]string` and `.golangci.yml` runs `exhaustive` with `check: [switch, map]`, so a reason added without a column fails the lint. Counting is never capped, and a URL rejected in one channel but classified live in another is excluded from the counts (its line stands — it records what that channel's fetch answered). `recheckManaged` passes a nil recorder: its URLs are existing managed sources, not candidates, and `rechecked`/`revived` ride the cycle's terminal `private.yaml updated` / `no change` line instead.
